# 黎明教育教务管理系统

单店教培机构使用的 Node.js + SQLite 教务系统，覆盖排课、学生费用、充值、教师薪资、员工、开销、账号权限、操作日志和数据备份。正式部署使用 Docker Compose，应用数据保存在 `liming_data` 持久卷中。

## 本地运行

要求 Node.js 24 或更高版本。首次运行：

```powershell
npm.cmd run init
npm.cmd start
```

默认访问 `http://127.0.0.1:3000`。正式环境参数通过 `.env` 或容器环境变量提供；README、日志和 Excel 均不得记录密码、Cookie、Session、Token、Secret、服务器绝对路径、Docker 凭据或 SSH 信息。

## 数据中心

`设置 → 数据中心` 沿用原 `audit` 页面权限键，固定显示“数据导入导出、备份设置、备份记录”三个区域。老板兼容角色 `owner、boss、admin、老板、管理员` 均可进入；其他账号必须明确拥有 `audit` 权限。前端隐藏无权限入口，后端仍独立返回 403。

页面加载顺序是：登录及权限检查 → 切换 `audit` 视图 → `loadActiveViewData()` → `refreshBackupData()` → `GET /api/data-center` → `renderAudit()` → 绑定事件。接口失败时仍保留三个区域，并显示安全错误摘要和“重新加载”。缺少百度配置或备份目录只显示中性状态，不阻止页面打开。

`backup_records` 沿用原表并通过幂等增量列兼容旧数据库。旧记录显示为 `legacy_core_zip`，旧备份永不参与新体系清理或保留策略。备份目录状态检查不会为了打开页面而创建目录。

### 数据完整性预检与问题修复

完整导出、手动备份和计划备份共用数据完整性预检；预检未通过时禁止生成备份，避免把已知关系错误固化为看似可恢复的文件。“账号角色关系无效”表示账号保存的角色为空、对应角色不存在，或保存了历史角色名称而不是当前角色代码。当前 `roles` 表没有启停字段，因此系统不会凭空报告“角色已停用”；以后若角色模型增加状态，必须另行定义并测试该原因。预检只诊断，不会自动绑定老板、管理员或其他角色，也不会删除账号或角色。

老板兼容角色 `owner、boss、admin、老板、管理员` 和显式拥有 `audit` 页面权限的账号可以查看预检分类、详情、重新检查及下载 CSV；普通教师和员工没有入口，直接请求详情也返回 403。详情显示问题类型、账号记录 ID、账号、姓名、当前角色 ID/代码/名称、真实错误原因及建议处理方式。账号管理权限同时存在时可点击“前往账号权限”，页面会切换到“设置 → 账号权限”并定位对应账号；无账号管理权限时仍可查看诊断，但不显示跳转按钮。修复角色并保存后回到数据中心点击“重新检查”，结果通过后即可再次执行备份。

详情 API 为 `GET /api/data-center/preflight/details`；单条安全诊断为 `GET /api/data-center/preflight/issues/:code/records/:id`，不存在返回 404；CSV 为 `GET /api/data-center/preflight.csv`。详情失败会显示脱敏摘要和“重试”，不会点击无反应。API 和 CSV 都不查询或序列化密码、密码哈希、Cookie、Session、Token、App Secret 等认证凭据。

### 数据中心控件与备份设置布局

Excel 导入保留原生 `input[type=file]`，但视觉隐藏并由系统按钮触发：未选择显示“选择Excel文件 / 尚未选择文件”，选择后显示“重新选择 / 文件名”。按钮支持鼠标、Tab、Enter 和 Space；仅接受 `.xlsx`，长文件名省略显示并用 `title` 提供完整名称。上传预检、失败后重选和成功后的状态清理仍沿用原导入流程，不引入第三方上传组件。

桌面端备份设置维持等宽、顶部对齐的两张卡片，但不强制相同内容高度。服务器本地备份增加“备份中包含操作日志”，默认关闭，同时作用于立即备份和本地计划备份。默认保留值仍为每日 14、每月 12、手动 20。百度卡片依次分为“远端目录/风险确认/操作日志”“启用/频率/时间/时区”“周几或月几/保留数/重试数”三组，底部提供“立即备份到百度网盘、保存百度备份设置、测试连接、解除授权”。1100px 以下卡片上下排列，760px 以下字段改为单列。

1024px 及以上桌面端展开侧栏宽度为 `208px`，品牌区、主内容网格和二级菜单缩进同步收窄；长菜单允许换行而不截断。折叠宽度仍为 `72px`，移动端继续使用原抽屉/单列规则，截图和打印布局不随桌面宽度强制变化。

## 完整 Excel v4

- 文件名：`黎明教育_全量数据_YYYYMMDD_HHmmss.xlsx`
- `file_type=liming_full_data_excel`
- `format_version=4`
- 空白模板：`黎明教育_全量数据导入模板_v4.xlsx`
- 合成验收文件：`artifacts/黎明教育_全量数据_合成验收_v4.xlsx`

同一 v4 导出器用于网页导出、手动备份、自动备份、服务器本地备份及百度明文备份。初始化导入、完整覆盖恢复、验证器和恢复演练使用同一字段契约。v3 及更旧文件不会被静默识别为 v4，导入会明确提示“文件版本不兼容，请重新导出或下载 v4 文件”；旧备份记录仍可下载，但其记录版本不会改变。

操作日志采用 v4 向后兼容的可选元数据，不改变工作表名称、顺序或列：网页“导出全部数据”默认包含日志；服务器本地备份默认不包含；百度备份默认包含。未包含时“操作日志”仍保留表头且数据行为 0，“导出说明”和 `__恢复元数据` 同时写入 `operation_logs_included=false`。旧 v4 未含该新增元数据时按历史行为解释为 `true`。验证器拒绝“标记不含日志但工作表有数据”的文件；完整覆盖恢复遇到 `false` 时不清空、不覆盖目标数据库已有操作日志，空系统初始化则保持日志为空。备份记录以“包含操作日志/不含操作日志”显示该策略。

完整 Excel 含 22 张可见业务表和 4 张 `veryHidden` 恢复表。可见表用于人工查看和受控编辑；主键、外键、精确空值、兼容字段和密码哈希只进入必要的隐藏恢复映射。不含公式、宏、外部链接、Session、Cookie、Token、Secret、服务器路径、Docker/SSH 信息、IP 或 User-Agent。公式前缀用户文本始终写为普通字符串。

### v4 字段规则

- 学生“单人费用”是课程对该学生实际采用的费用，保留两位小数。页面“规则费用”来自学生单价和费用标准，可重新计算，因此 v4 Excel 不重复保存；学生单价、费用标准、单节覆盖和课程原始数据仍完整恢复。
- 教师“教师薪资”取已上课程持久化的实际薪资。页面“规则薪资”按教师、年级、科目、学生集合、每 2 小时薪资及课程时长实时计算，因此 v4 Excel 不重复保存；教师薪资规则和课程原始数据仍完整恢复。
- 充值“月份”只来自该记录原始 `month_key`，显示为 `YYYY年M月`。即使充值日期为空也保留业务月份；绝不根据充值日期推断。排序为月份、充值日期、原始 ID。
- 期初余额是每名学生一条的全局基础余额，与月份无关，也不把计算后的月末余额当成期初余额。可见表、隐藏关系映射、字段定义、模板、导入和验证器均不包含期初余额 `month_key`。
- `student_opening_balances` 以 `student_name` 唯一约束保证当前姓名关系模型下每名学生最多一条。若旧库同一学生存在不同业务值，启动迁移会以 `OPENING_BALANCE_MIGRATION_CONFLICT` 中止并输出冲突清单，不会选最新、求和、删除或改写原表。
- 学生单价和教师薪资规则的可见价格状态统一为 `已设置、未设置`，页面、筛选、Excel 和模板共用 `src/domain/price_status.js`。有效金额且技术状态允许匹配时为“已设置”；金额为空、为零或教师规则技术状态不允许匹配时为“未设置”。`is_active` 继续作为内部恢复字段保留，完整 Excel 的 `veryHidden` 关系映射精确保存它，用户界面不显示“已停用”、布尔值或启停字段。自动/手动只属于费用来源，不再冒充价格状态。
- 学生档案一人一行，六个年级各有起始/截止日期，加“已毕业日期”共 13 列。页面年级阶段编辑器使用相同阶段定义。阶段日期采用 `YYYY-MM-DD`，截止不能早于起始，各阶段不得重叠；填写了阶段时，当前年级必须存在对应阶段。

### 全局期初余额与数据库迁移

新表字段为 `id、student_name、grade、opening_actual_balance、opening_gift_balance、notes、created_at、updated_at`，且 `UNIQUE(student_name)`。当前学生关联仍以姓名为准；在未来引入稳定学生 ID 前，重名学生是明确限制。

启动时的幂等迁移先只读扫描旧表：单条记录直接迁移并忽略旧月份；同一学生的年级、实际余额、赠送余额和备注完全一致时保留最早 ID 的一条，并在操作日志记录全部来源 ID 和原月份；任一业务值不同时，在写事务开始前抛出冲突，清单包含每条旧记录的 ID、年级、两类余额、备注、原月份和时间字段。冲突时旧表及全部记录保持不变，必须先由人工确定唯一权威值再重新启动。

期初余额页面固定显示“选择、学生姓名、年级、期初实际余额、期初赠送余额、备注”，新增与编辑只处理学生、年级、两类余额和备注。备注列桌面端最小宽度为 280px，并占用剩余空间；行内文本域宽度为 100%，普通长文本及连续长字符均在单元格内换行。窄屏不压缩学生和金额列，由表格容器提供横向滚动。该显示调整不改变 Excel 列或数据库字段。顶部月份切换不刷新或过滤该列表。同一学生重复新增返回“该学生已存在期初余额，请直接编辑原记录。”旧客户端暂时仍可携带 `month_key`，服务端忽略且不持久化，并在响应中返回弃用说明；删除该兼容入口必须放到后续独立版本迁移中。

余额计算继续使用既有账本算法：全局期初实际/赠送余额作为唯一开端，再累计到目标月份截止日的充值和已生效消费；欠费抵扣、现金与赠送使用顺序、请假/试听等不收费状态、单节覆盖和学生单价匹配规则均未重写。2 月、3 月和 6 月跨月回归会核对同一全局起点、跨月充值、单节覆盖及不收费状态。

完整 Excel 当前为 v4。期初余额可见列和空白模板固定为“学生姓名、年级、期初实际余额、期初赠送余额、备注”；隐藏恢复映射不保存废弃月份。恢复写入后继续受学生唯一约束保护。手动备份、自动备份和导入预检均使用同一全局模型，不会再出现“期初余额第 2 行缺少月份”。

### 隐藏恢复工作表与安全

1. `__恢复元数据`：文件类型、格式版本、导出时间、schema 来源、`operation_logs_included` 和每张表摘要。
2. `__关系映射`：无法从可见列可靠重建的主键、外键、排序、空值和兼容字段。
3. `__账号认证数据`：账号及密码哈希，仅用于恢复原登录凭据。
4. `__长文本分片`：精确恢复所需的长文本分片和摘要。

任意单元格最多 30,000 个 UTF-16 代码单元；超长恢复内容按 Unicode 安全边界分片并校验 SHA-256。写出后会重新解析 OOXML、校验 XML、隐藏表状态、表级摘要和恢复关系。空白模板不含隐藏表、内部 ID 或密码哈希；账号模板中的初始密码在导入时立即使用随机盐 PBKDF2-SHA256 哈希。

## 页面首次加载

原问题的根因是：首页使用轻量 `/api/bootstrap?lite=1` 后，页面状态对象已经存在；首次切换到费用汇总、费用明细、学生单价、教师薪资汇总或教师车费明细时，旧判断复用了轻量状态中的空派生数组，没有请求当前月份的完整 bootstrap。切换月份或整页刷新恰好触发了完整请求，所以数据才出现。

现在 `viewNeedsFullBootstrap()` 明确列出五个页面，并用 `full_bootstrap_key=月份 + 是否包含停用档案` 标识缓存。`load()` 首次进入时发现 key 缺失即请求完整 bootstrap；成功后记录 key。月份切换、数据写入和脏标记会更新或失效 key。流程为：显示当前页面加载态 → 请求当前月份 → 检查加载代次 → 写入状态 → 立即 render。返回页面可复用同月份有效缓存，不会复用其他月份或轻量缓存；请求失败走统一错误和重试界面，不强制刷新、不伪造月份切换、不使用延时盲刷。

真实 Chromium 回归：

```powershell
npm.cmd run test:page-first-load
```

每个目标页面均从独立合成数据库、全新服务和全新浏览器会话开始，登录老板账号并停留首页后首次点击；测试检查标题、当前月份、DOM 数据行、200 网络响应、Console 未捕获错误、返回首页再进入，以及 7 月/8 月往返缓存。除原五个页面外，充值记录、期初余额、班级管理、学生档案、教师课时明细、教师薪资规则和教师档案也纳入首次加载回归。

## 百度网盘明文 Excel 与 SHA-256 配对备份

服务器本地备份不依赖百度账号或网络。本地 v4 Excel 完成结构验证并原子发布后，远端流程直接上传原 `.xlsx`，同时上传同名 `.xlsx.sha256`；不会为了上传再次复制完整 Excel。远端文件名分别为 `黎明教育_全量数据_YYYYMMDD_HHmmss.xlsx` 和 `黎明教育_全量数据_YYYYMMDD_HHmmss.xlsx.sha256`。

HTTPS 只保护传输过程。百度网盘中的 Excel 没有应用层文件加密，包含学生、课程、充值、账号权限和账号认证哈希等敏感数据，必须按完整数据库同等级保护，不得公开分享。首次启用自动上传前必须勾选“我已知晓百度网盘中将保存未加密的完整备份文件”；未确认时后端以稳定错误码拒绝启用。建议百度账号启用可靠密码及安全验证。

三步配置流程：

1. **填写百度应用信息**：老板或显式拥有 `audit` 的数据中心管理员只填写 App Key、App Secret，并核对只读回调地址；不再二次输入老板密码或确认文字。未配置及点击“重新配置”后的两个输入框均为空。App Key 使用独立字段名和 `autocomplete="off"`，不会取登录账号（包括 `Qing`）；App Key 和 App Secret 保存后都不回显，状态接口只返回两个“是否已配置”布尔值。
2. **连接百度网盘**：完成 OAuth 授权。授权 state 随机生成、10 分钟有效且只能使用一次；Token 自动刷新。回调只把 `baidu=connected|failed|denied` 作为一次性结果标记。前端显示一次提示、刷新并定位数据中心，随后用 `history.replaceState` 删除 `baidu、code、state`，保留其他查询参数和 hash，不重新加载页面，刷新后也不会重复提示。
3. **测试并启用**：按授权、连接、测试目录、普通文件上传、校验文件上传、普通文件下载、校验文件下载、SHA-256 完整性、两个文件清理分别记录。只有双上传、双下载和完整性校验均成功，核心测试才通过。清理失败独立显示“连接及完整性测试通过，但测试文件清理失败”，并列出仍需人工处理的 `/apps/` 测试路径。

测试失败响应只含阶段、稳定内部错误码、百度 `provider_code`、HTTP 状态、分步布尔值和清理状态，不含 Token、Secret、授权 Code 或带 Token 的下载链接。下载流程检查 `filemetas`、`dlink`、重定向后的 HTTP 与 Content-Type，并拒绝把 JSON 错误体当文件字节。删除接口单独兼容 `errno=0`、`taskid/task_id` 和特殊成功体；响应不明确时复核文件是否已不存在。过去“远端看见上传后又删除、页面仍失败”可能来自双文件下载/校验中的真实失败，也可能来自通用 JSON 解析误判删除响应；现在页面“查看测试详情”会显示准确阶段，不能再由上传现象推断整个流程成功。

状态轮询只更新配置、授权、测试和自动上传状态。远端目录、风险确认、频率、时间、周/月执行日、保留数、重试数及日志选项进入前端 dirty draft；测试成功或失败以及后台刷新都不覆盖草稿，保存失败也保留当前输入，保存成功后以服务器值作为新基线。

百度自动备份与本地自动备份完全独立。频率固定为仅手动、每天、每周、每月；默认每周三 `03:30 Asia/Shanghai`，月执行日默认 1 且限制 1—28，远端保留 20 组，失败重试 3 次。仅手动不参加计划；其他频率各使用 `full-data-remote:<frequency>:<period>` 唯一键。到点时按百度日志选项新生成并验证 Excel；远端失败保留本地文件和同一记录，按 10、30、120 分钟节奏重试，成功后重启服务也不会重复该周期。分钟级调度器只检查是否到期，不会每分钟生成备份。

远端保留以成功上传并校验的 Excel 与 `.sha256` 为一组，从最旧未固定记录开始成对删除；固定记录跳过，至少保留一组，部分删除明确记录，不处理 `.enc` 历史记录，也不允许处理 `/apps/` 以外路径。本地保留策略不会因百度启停而改变。

持久设置键为：`full_backup_local_include_operation_logs`、`full_backup_remote_include_operation_logs`、`full_backup_remote_frequency`、`full_backup_remote_time`、`full_backup_remote_weekday`、`full_backup_remote_monthday`、`full_backup_remote_timezone`、`full_backup_remote_retention`、`full_backup_remote_retry_count`、`full_backup_remote_directory`、`full_backup_remote_plaintext_acknowledged`；百度启用状态继续使用兼容键 `full_backup_remote_enabled`。网页手动导出的日志选项仅为请求参数，不写服务器设置。

环境变量只保留以下三个可选替代来源：

```text
BAIDU_APP_KEY
BAIDU_APP_SECRET
BAIDU_REDIRECT_URI
```

网页保存的私密配置位于 `DATA_DIR/backups/full-excel/.secrets/baidu-config.json`，结构只含 `app_key、app_secret、redirect_uri、last_test_at、last_test_result`。OAuth Token 单独位于 `DATA_DIR/backups/full-excel/.secrets/baidu-token.json`。`.secrets` 目录权限设计为 `0700`，两个文件为 `0600`，由 Docker 持久数据卷保存；它们不进入 Excel、Git、普通设置响应或操作日志。远端目录仍由数据库设置保存，默认 `/apps/liming-course-system`，路径必须位于 `/apps/` 下且拒绝穿越。

上传前会重新检查本地文件仍位于受管目录、不是符号链接、Excel 结构有效且本地 sidecar 与文件摘要一致。大文件沿用分块上传，预创建、分块和最终创建请求失败时最多尝试三次。Excel 与 sidecar 分别记录远端文件 ID、路径和状态，另记录远端完整性状态与更新时间。任一上传失败都保留服务器本地备份；若只成功一个文件，记录“部分上传失败”，人工重试会重新处理整对文件。

下载远端备份时，服务端先下载 `.xlsx` 和 `.xlsx.sha256`，重新计算 SHA-256 并比较文件名和摘要，再验证 v4 Excel 结构；sidecar 缺失、摘要不一致或 Excel 无效都会阻止交付及后续恢复。浏览器下载响应禁止缓存，并在下载前提示这是未加密敏感文件。删除远端备份时分别尝试删除两个文件；部分删除会分别记为成功和失败，不伪装成全部成功。

开发环境中若存在以 `.enc` 结尾的旧远端记录，页面只显示“旧版加密远端备份”。新流程不会上传、改名、下载为普通 Excel 或自动迁移这些旧记录。这个兼容标识不保留旧的加密上传实现。

常见处理：未配置先填写应用信息；未授权先连接；测试失败按页面重新授权并测试；回调错误核对协议、域名、端口及完整路径；sidecar 缺失或摘要不一致时禁止恢复并重新生成可信备份；远端失败不影响已发布的服务器本地备份。当前分支使用模拟百度响应测试，没有连接真实百度账号，也没有改变正式服务器。

## 回滚与限制

回滚代码可在未合并分支上执行 `git revert <本轮提交>`；不要 reset/force-push，不要删除数据库或既有备份。若未来已经部署，先停止新的导入/备份任务，再回滚代码并重建应用。代码回滚不会自动回滚数据库；覆盖恢复前必须使用已生成并验证的完整 Excel。当前正式服务器没有因本分支发生任何变化。

已知限制：Microsoft Excel 兼容性最终以人工打开为准；数据库从未持久化的历史派生数据无法凭空恢复；诊断审计历史和通知完成历史不属于核心恢复范围；完整 Excel 含敏感业务数据及隐藏密码哈希，必须按完整数据库同等级保护；百度网盘依赖外部网络和 OAuth，远端保存的是明文 Excel，本地与远端状态分别记录。
