# 黎明教育教务管理系统

单店教培机构使用的 Node.js + SQLite 教务系统，覆盖排课、学生费用、充值、教师薪资、员工、开销、账号权限、操作日志以及数据备份。正式部署使用 Docker Compose，应用数据保存在 `liming_data` 持久卷中。

## 本地运行

要求 Node.js 24 或更高版本。首次运行：

```powershell
npm.cmd run init
npm.cmd start
```

默认访问 `http://127.0.0.1:3000`。正式环境参数通过 `.env` 或容器环境变量提供；README、日志和 Excel 均不得记录密码、Cookie、Session、Token、Secret、服务器绝对路径、Docker 凭据或 SSH 信息。

## 数据中心

`设置 → 数据中心` 沿用原 `audit` 页面权限键，避免破坏旧角色。页面固定三个区域：

1. 数据导入导出：导出完整 Excel、下载空白模板、上传预检、空系统初始化和完整覆盖恢复。
2. 备份设置：手动备份、每日调度、Asia/Shanghai 时区、失败重试、服务器保留数和百度网盘配置状态。
3. 备份记录：本地/远端状态、大小、SHA-256、备注、固定、下载、校验、重试上传和受保护删除。

完整备份包含 22 张可见业务表和 4 张 `veryHidden` 恢复表；空白模板包含 22 张可见业务表及“填写说明”，不含内部恢复数据。页面缺少百度配置、加密密钥或备份目录时会显示中性状态，不会阻止数据中心打开。

### 页面兼容和故障降级

旧版本曾因数据中心列表调用缺失的显示函数而在存在旧备份记录时抛出 `ReferenceError`。当前加载顺序为：登录和权限检查 → 切换 `audit` 视图 → `loadActiveViewData()` → `refreshBackupData()` → `GET /api/data-center` → `renderAudit()` → 事件绑定。接口失败仍会保留三个固定区域，并显示安全错误摘要与“重新加载”。

`backup_records` 沿用原表，通过幂等增量列兼容旧数据库。旧记录继续显示为 `legacy_core_zip`，旧文件永不参与新体系的自动清理。未配置百度时不创建 Token 文件；未配置加密密钥时只禁用远端上传；备份目录状态检查不会为了打开页面而创建目录。

老板兼容角色 `owner、boss、admin、老板、管理员` 均可进入；其他账号需要明确拥有 `audit` 权限。前端隐藏无权限入口，后端仍独立返回 403。

## 完整 Excel v2 设计

- 文件名：`黎明教育_全量数据_YYYYMMDD_HHmmss.xlsx`
- `file_type=liming_full_data_excel`
- `format_version=2`
- 用途：人工查看、完整恢复、服务器本地备份和百度网盘加密备份。
- 用户可见区域只显示页面或业务定义中的字段，不把数据库所有列直接暴露给用户。
- 不保存费用汇总、薪资汇总、统计、合计等可重新计算结果。
- 不含公式、宏或外部链接；以公式前缀开头的用户输入仍写为普通字符串。
- 时间元数据使用 UTC；页面计划日期明确使用 Asia/Shanghai。

完整恢复需要的主键、外键、排序、兼容字段和密码哈希保存在最少量的内部表中。创建时间、更新时间、关联 ID、原始技术状态、恢复标记、路径、IP、User-Agent 和原始 JSON 不出现在可见业务表中。

### 22 张可见工作表和列顺序

顺序是格式契约，验证器会拒绝缺失、重命名、换序或增加未知列的文件。

1. **导出说明**：项目、内容。
2. **所有课程数据**：授课老师、日期、星期、时间、教室、状态、年级、科目、学生、备注。
3. **所有学生费用明细**：学生姓名、授课老师、日期、状态、星期、时间、教室、年级、科目、备注。
4. **所有充值记录**：学生姓名、年级、本月实际充值、本月赠送充值、充值日期、备注。
5. **期初余额**：月份、学生姓名、年级、期初实际余额、期初赠送余额、备注。
6. **所有学生单价**：学生、年级、科目、学生集合、单价、备注。
7. **所有班级管理**：老师、年级、科目、学生集合、班级名。
8. **学生档案**：姓名、当前年级、年级时间界定、监护人、电话、状态、入学日期、离校日期、备注。
9. **所有教师车费明细**：月份、教师、周次、开始日期、结束日期、金额、备注。
10. **所有教师课时明细**：授课老师、日期、状态、星期、时间、教室、年级、科目、学生、备注。
11. **所有教师薪资规则**：老师、年级、科目、学生集合、每2小时薪资、是否启用、备注。
12. **教师档案**：姓名、电话、状态、入职日期、离职日期、备注。
13. **员工**：姓名、角色、计薪、基础工资、日薪、标准天数、手机、状态、入职、离职、备注。
14. **所有员工薪资**：月份、员工姓名、实际工资、奖金、扣款、备注。
15. **所有员工考勤**：员工姓名、考勤日期、状态、计薪单位、工时、原因、备注。
16. **所有日常开销**：日期、类别、金额、商家、备注。
17. **系统设置**：设置项、设置值。
18. **基础数据**：类别、名称、状态、排序。
19. **费用标准**：年级、人数、单人费用、查找键、说明。
20. **操作日志**：操作人、操作账号、操作类型、操作内容、结果、操作时间。
21. **角色管理**：角色名称、角色说明、页面权限、操作权限、状态。
22. **账号管理**：账号、姓名、角色、绑定教师、页面权限、账号状态。

课程和课时按日期、当天顺序、时间、教师排列。学生费用明细和教师课时明细是人工查看用的派生明细，不是第二恢复来源；恢复时由课程与相关规则重新计算。充值表只包含真实持久化充值，不生成未登记提示、零金额提示或汇总行。期初余额导出所有月份的原始期初值，不把月末计算余额写入。

学生单价只保存数据库实际存在的规则；系统没有保存过的历史版本无法凭空恢复。教师薪资规则保留启用和停用记录，但不导出薪资汇总。所有其他运营表均一条原始记录一行，不生成统计和合计。

### 年级、角色和账号的合并格式

每名学生只占一行，多个年级阶段使用全角分号分隔：

```text
初三：2025-09-01至2026-06-30；高一：2026-07-01至
```

空结束日期表示当前阶段。导入严格验证日期、起止顺序及阶段不重叠。

角色的页面权限和操作权限、账号的绑定教师和个人页面权限也在各自一行内使用全角分号分隔。导入程序按稳定名称/权限键解析，再恢复关系；内部主键与外键不显示在业务表中。

### 系统设置和基础数据

系统设置只显示用户可配置且已进入明确白名单的项目，例如当前月份、课程时间和自定义状态。内部迁移标记、诊断设置、百度凭据、加密密钥、Session、Cookie、服务器路径和容器信息均排除。

基础数据由当前数据库中的教师、年级、科目、时间、教室和课程状态等真实来源生成，用于人工参考；它不是重复恢复来源。

### 隐藏内部恢复工作表

完整备份最后包含以下 4 张 `veryHidden` 表，空白模板不包含它们：

1. `__恢复元数据`：文件类型、格式版本、导出时间、schema 来源和每张表摘要。
2. `__关系映射`：无法从业务列可靠重建的主键、外键、排序、空值和兼容字段。
3. `__账号认证数据`：账号及密码哈希，仅用于恢复原登录凭据。
4. `__长文本分片`：精确恢复需要的长文本分片和摘要。

验证器检查隐藏表名称、顺序、`veryHidden` 状态、列结构、表级 SHA-256、关系及长文本摘要。它们不要求用户编辑，也不会出现在模板中。Session 和 Token 不备份、不恢复。

审计事件、数据检查记录、数据检查忽略项、字段定义、教师调整兼容数据、角色/账号筛选预设、课程通知完成记录、家长群问候记录和账号认证数据不再作为可见表。筛选预设等确需恢复的数据以最小关系映射保存；可重新生成的诊断历史不进入恢复范围。

## Excel 字符串安全与损坏修复

旧版写入器把任意长度文本直接写入 `inlineStr`。审计 JSON 达到 Excel 单元格 32,767 个 UTF-16 代码单元边界后，Microsoft Excel 会修复 `/xl/worksheets/sheet33.xml` 的字符串属性。v2 统一执行：

- 任意单元格最多 30,000 个 UTF-16 代码单元；未分片超限立即失败。
- 需要精确恢复的长文本按 Unicode 代理对安全边界切成不超过 30,000 的分片。
- 每组记录来源表、来源记录标识、字段、分片序号、总数、文本和整段 SHA-256；恢复后重组并复核摘要。
- 可见操作日志仅显示安全预览；完整技术内容只在确属恢复范围时进入隐藏映射/分片。
- 写出时使用合法 `inlineStr` 和 `xml:space="preserve"`；读取器同时验证 `sharedStrings` 索引。
- 非法 XML 控制字符及损坏的 Unicode 代理字符被安全替换，公式、宏和外部链接被拒绝。
- 生成后重新解析全部 OOXML 部件，检查 XML 结构、单元格长度、隐藏表摘要和恢复关系。

## 完整备份与空白模板

完整备份含真实数据、22 张可见表和 4 张隐藏恢复表，可用于完整覆盖恢复。空白模板文件名为 `黎明教育_全量数据导入模板_v2.xlsx`，只含 22 张可见业务表、填写说明和合成示例，不含真实数据、内部 ID、隐藏映射或密码哈希。

模板的账号表额外使用“初始密码”。初始化导入时立即用随机盐 PBKDF2-SHA256 哈希，明文不会进入数据库、日志或生成的完整备份。完整备份则把已有密码哈希放在 `__账号认证数据`，因此恢复后原密码继续可用。

## CLI

导出、验证和恢复：

```powershell
npm.cmd run excel:full:export -- --db "D:\data\liming-local.sqlite" --output "D:\backup\全量数据.xlsx"
npm.cmd run excel:full:verify -- --input "D:\backup\全量数据.xlsx"
npm.cmd run excel:full:restore -- --db "D:\empty\liming-local.sqlite" --input "D:\backup\全量数据.xlsx"
```

模板和导入：

```powershell
npm.cmd run excel:template -- --output "D:\backup\黎明教育_全量数据导入模板_v2.xlsx"
npm.cmd run excel:import -- preview --input "D:\backup\filled.xlsx"
npm.cmd run excel:import -- execute --input "D:\backup\filled.xlsx" --db "D:\empty\liming-local.sqlite" --mode initialize
npm.cmd run excel:import -- execute --input "D:\backup\全量数据.xlsx" --db "D:\data\liming-local.sqlite" --mode overwrite --backup-dir "D:\backup\pre-import"
```

`initialize` 要求目标是 schema-only 空数据库。`overwrite` 在写入前于受管目录创建并验证 v2 备份，然后在一个事务中按依赖顺序恢复：设置和档案 → 年级/价格/班级规则 → 课程/充值/余额/调整 → 员工数据 → 角色/权限/账号关系 → 操作日志。结构、关系、摘要或数据库完整性任一失败均回滚。

## 本地、自动和百度备份

手动和自动备份均调用同一 v2 导出器，先在受管 staging 中生成并验证 Excel，再原子发布 `.xlsx` 与 `.sha256`。`backup_records.format_version` 记录为 2；`schedule_key` 防止同一计划日重复成功。调度按 Asia/Shanghai 计算，失败重试和保留策略只作用于新受管文件。

服务器备份目录仍位于应用持久数据目录的 `backups/full-excel/`。目录和文件使用私有权限，Nginx 不挂载数据卷；下载接口要求权限并返回 `Cache-Control: no-store`。

百度网盘采用开放平台接口。上传前在本地临时文件中使用 AES-256-GCM 加密，远端只接收密文；Token 保存在私有文件中，状态接口不回传令牌。密钥遗失将无法解密远端副本。百度未配置是中性状态，不影响本地备份健康。

### 数据完整性预检与期初余额月份

全量导出、手动备份、自动备份、覆盖恢复前备份以及百度上传前的本地备份共用只读预检。预检至少检查期初余额月份、课程日期、已有充值日期的格式、学生/教师/员工姓名、价格与班级关键字段、账号角色及恢复关系。现有业务模型允许旧充值记录不填写具体日期，因此空充值日期原样保存，只有非空但格式非法的值才阻断。失败使用稳定错误码 `BACKUP_DATA_PREFLIGHT_FAILED`：已创建的 `backup_records` 记录转为 `failed`，但不发布 Excel、`.sha256` 或 staging 文件，也不会启动远端上传。

“期初余额缺少月份”的根因是旧的独立期初余额 Excel 导入器曾把 `month_key` 固定写成空字符串，而表结构允许该旧值；完整 Excel 映射没有丢失数据库中本来有效的月份。当前规则如下：

- 数据库中已有合法月份时，导出、可见“期初余额”表、`__关系映射`、验证和恢复统一使用 `YYYY-MM-01`，可见值与内部恢复值不一致会被拒绝。
- 不用页面当前月、备份执行月或记录创建日期填补旧空值，也不丢弃错误记录。
- 旧备注中若只有一个明确的“YYYY年M月.xlsx”来源，可作为页面建议，但不会静默写库；老板仍需在期初余额页逐条选择并确认。
- 修复前显示记录 ID、学生、年级、实际余额、赠送余额和原备注；修复只更新目标记录的月份，并写入审计事件和操作日志，然后重新预检。
- 新建、编辑和独立 Excel 导入期初余额都必须明确填写月份，从源头阻止新增空月份。

数据中心在预检失败时显示问题类型、数量、前几条记录、“查看问题记录”“重新检查”和“下载错误清单”。普通日志只保存稳定错误码，不保存完整业务行或秘密配置。

### 小白配置百度网盘

服务器本地备份与百度网盘备份是两份独立副本：本地备份无需百度账号或网络即可工作；百度备份只在本地备份成功后，把临时加密得到的 `.xlsx.enc` 上传到远端，不会上传明文 Excel。接入前先阅读[百度网盘开放平台](https://pan.baidu.com/union)和[百度官方 OAuth 2.0 接入指南](https://openauth.baidu.com/doc/)，页面名称及申请条件以官方最新文档为准。

1. 在百度网盘开放平台创建应用并申请所需网盘权限。App Key 用来标识应用；App Secret 用来证明服务端应用身份，必须保密；OAuth 回调地址用于接收一次性授权码；备份加密密钥用于 AES-256-GCM 加密远端副本。
2. 后端真实回调路由固定为 `/api/data-center/baidu/callback`。本地示例是 `http://127.0.0.1:5177/api/data-center/baidu/callback`；正式示例是 `https://你的正式域名/api/data-center/baidu/callback`。百度开放平台登记值、`BAIDU_REDIRECT_URI` 和实际访问协议/域名/路径必须完全一致。系统只显示明确配置的正式地址，不根据浏览器来源猜测。
3. 在服务器环境变量中配置四项，普通网页只显示“已配置/未配置”，不保存或回传真实值：

```env
BAIDU_APP_KEY=
BAIDU_APP_SECRET=
BAIDU_REDIRECT_URI=
BACKUP_ENCRYPTION_KEY=
```

4. 在可信终端生成 32 字节随机密钥：

```powershell
npm.cmd run backup:key:generate
```

Linux 使用 `npm run backup:key:generate`。命令只输出一次，不写文件、不写数据库。立即离线保存；密钥丢失后，百度网盘中的既有加密文件无法恢复。不要把 Secret 或密钥提交 Git、写入 Excel、聊天记录或普通日志。

5. 保存环境变量后，由部署管理员重建或重启应用容器，例如在正式 Compose 工作目录执行 `docker compose up -d --no-deps --force-recreate app`。本说明不授权在开发验收中操作正式服务器。
6. 返回“设置 → 数据中心 → 百度网盘备份”，确认 App Key、App Secret、回调地址和加密密钥四项都为“已配置”。缺任一项时，“连接/重新授权”“测试连接”和“启用百度网盘备份”保持禁用，并列出缺项；本地“立即备份”仍可用。
7. 四项齐全后点击“连接/重新授权”，在百度完成 OAuth；回到数据中心确认授权及 Token 状态，点击“测试连接”，最后再启用百度网盘备份。解除授权只删除本地受保护的 Token，不删除服务器备份。
8. 成功后在网盘远端目录确认只存在 `.enc` 文件。不要手工上传明文全量 Excel。Token 需要刷新时系统在实际调用前使用 Refresh Token；授权失效则重新授权。

状态接口 `GET /api/data-center/baidu/status` 只返回四项配置布尔值、授权状态、Token 状态、明确配置的回调地址、后端回调路由、远端目录、缺项和最近测试的安全结果。它不返回 App Secret、Access Token、Refresh Token、加密密钥或密码哈希。Token 文件位于应用数据目录的私有受管子目录，权限设计为 `0600`。

常见问题：回调不匹配时核对协议、域名、端口和完整路径；“尚缺少”时补齐环境变量并重新创建容器；Token 过期且不能刷新时重新授权；远端上传失败不影响已成功发布的服务器本地备份；密钥错误或丢失时不能绕过认证解密。当前正式服务器尚未因本分支配置或授权百度网盘。

人工验收步骤：

1. 用 Windows 版 Microsoft Excel 直接打开合成验收文件，不接受“修复后打开”。
2. 确认没有“部分内容有问题”或修复日志。
3. 确认可见工作表恰好 22 张且顺序一致，普通界面不显示内部表。
4. 检查中文、Emoji、空格、长操作说明、日期和金额显示。
5. 关闭文件且不保存，再运行验证 CLI；文件摘要应保持不变。
6. 用该文件恢复 schema-only 合成库，并验证数据库一致性和原账号密码。

正式部署前还必须在隔离目录使用正式数据库副本完成相同导出、Microsoft Excel 打开、验证和恢复演练。本分支不连接正式服务器；当前正式服务器没有因本分支发生任何变化。

## 回滚与已知限制

代码回滚：停止未部署的分支验证，检出本分支修改前的 commit；若未来已部署，应先停止新导入/备份任务，再回滚代码并重建应用，不能回滚或删除已有业务数据库。数据回滚必须使用导入前生成并验证过的完整 Excel，按“完整覆盖恢复”流程执行。旧备份永不参与新保留策略，不能用新验证器冒充 v2 文件。

已知限制：

- Microsoft Excel 的真实兼容性最终以人工打开验收为准；自动检查只证明 OOXML 结构及项目恢复契约通过。
- 数据库从未持久化过的历史单价、历史派生汇总无法凭空恢复。
- 数据检查/审计诊断历史及通知完成历史是明确排除项；它们不参与核心业务一致性比较。
- 完整 Excel 包含敏感业务数据及隐藏密码哈希，必须按完整数据库同等级保护。
- 百度网盘依赖网络、OAuth 和独立加密密钥；本地成功与远端失败分别记录。
- 回滚代码不会自动回滚数据库，任何覆盖恢复前必须先生成并验证备份。
