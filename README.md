# 黎明教育教务管理系统

面向单店培训机构的课程、学生费用、教师薪资和日常经营管理系统。本文件以当前代码为准，同时服务于机构管理员、新开发者和部署维护人员。

当前应用及主静态资源版本为 `20261024-summary-profile-layout`。本轮说明见“2026-10-24：费用看板、教师档案与筛选布局”；展开/折叠布局沿用10月18日实现。下文保留完整历史记录；历史课时操作及课时明细中的历史规则入口已移除，旧工资读取、特殊覆盖和独立薪资规则兼容能力仍保留。

## 1. 项目简介

系统覆盖排课、课程执行、学生收费、教师结算、员工与经营支出、权限、审计、完整 Excel 数据交换及备份。当前技术栈是 Node.js 24、内置 `node:sqlite`、原生 HTML/CSS/JavaScript 和无宏 `.xlsx`；正式环境由 Docker Compose 运行应用与 Nginx，SQLite 及受管文件持久化在 Docker Volume 的 `/app/data`。

这是单体应用：浏览器请求同一个 Node 服务提供的静态资源和 JSON API。SQLite 是当前唯一在线数据库，不应将仓库、容器可写层或 Excel 文件误认为数据库的替代品。

## 2. 功能总览

### 首页与排课

- **首页**：显示当日/近期课程、关键经营指标、数据质量和备份健康状态；“正在上的课程”和页面当前时间统一按 `Asia/Shanghai` 判断。桌面端当前课程、待办和人数统计由同一网格行自然拉齐，课程过多时只滚动课程列表；390px 下恢复自然堆叠。
- **课程总表**：按日期、老师、学生、年级、科目、状态等筛选课程，支持新增、复制、批量状态、批量修改公共字段和行级编辑。完整列出同一老师、教室和学生的时间冲突，支持局部修改所选课程，或再次确认后忽略冲突；后端重新核验，整批事务保存。
- **矩阵课表**：时间、老师和教室三种模式共用 196px 课程卡片与日期列口径，也共用标签与选择器紧邻的日期范围筛选；卡片高度随学生和备注自然增长，窄屏只滚动矩阵外层。
- **家长群课程截图**：生成个人、班级和班级合并发送卡片；简洁模式显示紧凑发送任务卡，复制图片与详细模式一致；详细模式从“课程通知”标题直接进入课程明细表，不再重复显示顶部学生、年级和科目摘要。
- **老师课程截图**：按老师生成课程安排截图；详细模式由“本周课程安排”标题直接进入课程明细表，不再生成独立老师身份行，表内“授课老师”列继续保留；简洁任务卡仅保留老师身份、年级、课程数及复制操作，不展示图片预览；实际复制和下载 PNG 仍为完整详细课表。

### 学生与收费

- **费用汇总**：汇总学生在选定期间内的充值、实际余额、赠送余额和消费；筛选区下方四张卡展示当月课程费用、实际/赠送期初结转、实际/赠送充值和实际/赠送期末余额，跟随月份、学生、年级及余额筛选。全部展示金额均为 0 的行只在页面隐藏，不删除记录，也不改变完整导出。
- **费用明细页面已下线**：导航和专用查询接口已移除；单节金额在学生查询课程弹窗核对与修改。底层明细计算继续服务汇总、余额、学生查询和完整Excel导出恢复。
- **充值记录**：记录实际充值、赠送充值、充值日期、结构化来源/渠道和备注；表格取消独立操作列，来源/渠道可直接在行内浮层修改，新记录默认微信，旧记录未保存渠道时明确显示“未记录”。年级与来源分析卡依次自然排列；渠道完整单行，备注按内容紧凑展示。
- **期初余额**：每名学生一条全局起点余额，不与月份绑定；页面年级来自学生档案当前年级，历史记录年级只作为导出快照，跨月余额从全局起点累计。表格按当前可见内容自适应列宽，备注内容单行，长备注悬停查看全文；金额仍支持负数和两位小数，且仅本页隐藏浏览器数字步进按钮。
- **学生查询**：聚合查看学生档案、课程、费用和余额。默认折叠显示13列已上课程规则汇总，支持单条规则费用、选择、批量规则设置及点击行打开原课程弹窗。展开直接替换为当前学生及日期内的一张完整逐节课程表，只有一行表头和一个批量实际费用入口，不嵌套子表；包含待上、请假及只有待上课程的分组。两种视图互斥，学生集合保持自然排序、完整单行及外层横向滚动。有效节数与总节数分别统计；价格状态筛选不恢复。课程明细共用单节费用编辑与批量预览确认；旧课程保持原收费来源，新建课程已上后采用个性规则优先的规则费用。写入独立检查原权限。看板、月份汇总、Excel和复制图片继续使用原始逐节账单数据。
- **独立学生单价页面已下线**：导航、独立渲染、筛选、批量弹窗及专属加载缓存已删除，改由学生查询管理。个性规则、收费标准、单节覆盖、业务状态和历史记录保留；旧权限作为定价编辑授权保留，不自动授予完整学生查询权限。
- **班级管理**：仅由全部月份、全部合法状态的真实课程生成列表，删除最后一节后自动消失，历史名称配置保留。按老师、年级、科目和标准化学生集合分组，同班允许不同课程类型，维护班级名，支持课程类型整班批量与弹窗单节修改，并与课程总表排课模式共用类型修改权限及接口；每名学生使用系统统一标签，集合完整单行且单个标签不拆分，横向空间不足时只滚动外层表格。
- **学生档案**：维护当前年级、各学段日期、监护人、电话、状态、入离校日期和备注；状态只允许“在读、暂停、已毕业、已流出”，并集中提示和定位年级阶段日期冲突。空监护人、备注显示“-”，自然列宽不拉伸余白；编辑仍保存真实空值。

### 教师、员工与经营

- **薪资汇总**：按月汇总基础课薪、绩效基数、绩效分数、绩效系数与车票合计；整数评分自动生成 K，未评分保留历史或手工 K；未人工设置的绩效系数默认 1.00，明确设置的 0.00 保留；缺少薪资规则仍提示待完善。
- **车费明细**：按月份、周次和老师记录教师车费。
- **课时明细**：先选择教师及日期范围，按班级展示实际课程起止日期、节数和含真实表名的薪资规则列；顶部显示有效/总课次、基础课薪、绩效基数及不含车费的课程总薪资。点击班级查看逐节基础课薪、自动/特殊状态并修改或恢复自动。默认隐藏离职教师，可取消隐藏。
- **薪资表**：先选择教师，在课时明细内管理该教师按日期生效的年级/课型公式；支持小班1—7人公式预览、通用模板和文本批量导入导出。课时明细中的“历史规则”和“历史课时操作”入口已移除；独立规则页面及兼容 API、旧金额读取、特殊来源和恢复自动的真实计算仍保留。
- **教师档案**：正常列表只展示全系统仍有真实课程的教师，不限月份、课程状态或在离职状态。最后一节课程删除后隐藏，重新排课后出现；教师基础资料、薪资、账号和排课候选继续保留。维护联系方式、在职状态、入离职日期和备注；空备注显示“-”，姓名、电话、日期及备注按内容确定列宽。
- **员工薪资**：维护非教师员工的月度实发、奖金、扣款和备注。
- **员工考勤**：记录考勤日期、状态、计薪单位、工时和原因。
- **日常开销**：记录日期、类别、金额、商家和备注。
- **经营概览**：汇总收入、教师薪资、员工工资、支出和毛利；数据不完整时会显示质量提示。

### 设置与治理

- **外观设置**：亮色、暗色、黑白及业务标签配色，保留设置页面入口；右上角账号菜单仅保留账号信息、修改密码和退出。
- **基础数据**：维护教室、科目、常用时间和课程状态等候选项。
- **费用标准**：按年级和人数维护默认单人费用。
- **数据中心**：预检、完整 Excel 导入导出、服务器本地备份、百度网盘副本和备份记录。
- **操作日志**：查询关键写操作和结果，可按需纳入完整 Excel。
- **账号权限**：维护账号、角色、教师绑定、页面权限与个人覆盖。

## 3. 技术架构

| 层 | 当前实现 |
| --- | --- |
| 运行时 | Node.js 24；`package.json` 要求 `>=24` |
| 数据库 | Node 内置 `node:sqlite`，单个 SQLite 主库，线上使用 WAL 模式时会同时存在 `-wal`/`-shm` |
| 前端 | `public/index.html`、`public/app.js`、`public/styles.css`，薪资工作流在 `public/salary-workflow.js`，共用课程明细在 `public/course-details.js`；无前端构建步骤 |
| 后端 | `src/server.js` 提供静态资源、认证、权限、API、初始化和迁移 |
| 领域计算 | `src/domain/` 提供状态、余额、薪资规则和课程类型公共规则；部分汇总与费用计算仍在 `src/server.js`，Excel 尚有历史兼容计算 |
| Excel | `src/excel/` 定义 v7 字段、读写、摘要验证和恢复，兼容读取 v4/v5/v6 |
| 备份 | `src/backup/` 管理本地 Excel、调度、保留和百度网盘副本 |
| 权限 | 系统角色默认权限 + 角色权限表 + 账号个人覆盖；后端仍逐路由校验 |
| 部署 | `docker-compose.yml`：`app` + `nginx`，命名 Volume `liming_data` |
| 入口 | 应用容器监听 5177；正式浏览器入口由 Nginx 暴露 80/443 |

当前 `Dockerfile` 使用 `node:24-alpine`，尚未固定镜像 digest。正式重建前应验证实际 Node、Alpine、SQLite 和镜像来源；不要把网络超时误记为供应链验证通过。

## 5. 本地开发

### 环境与安装

需要 Git、Node.js 24 或更高版本和 npm。主要 SQLite 测试依赖 Node 24 的 `node:sqlite`。不要为了测试擅自替换机器上的全局 Node；可使用隔离的 Node 24 容器。

```powershell
git clone <repository-url>
cd liming-course-system
npm install
npm run init
npm start
```

浏览器打开 `http://127.0.0.1:5177`。默认端口来自 `src/server.js` 和 `Dockerfile`，均为 **5177**。

PowerShell 使用 `npm.cmd` 可避开本机脚本执行策略：

```powershell
npm.cmd run init
npm.cmd start
```

Git Bash 使用：

```bash
npm run init
npm start
```

### 环境变量

| 变量 | 用途 | 默认值/说明 |
| --- | --- | --- |
| `NODE_ENV` | 运行模式 | Compose 中为 `production` |
| `PORT` | Node 监听端口 | `5177` |
| `DATA_DIR` | 数据目录 | 仓库内 `data/`；容器为 `/app/data` |
| `DB_PATH` | 显式数据库路径 | 默认 `${DATA_DIR}/liming-local.sqlite` |
| `SESSION_COOKIE_SECURE` | Cookie 是否仅 HTTPS | 正式环境应为 `true` |
| `APP_VERSION` | 页面和导出中的应用版本 | 未设置时使用代码内默认值 |
| `APP_GIT_COMMIT` | 导出和诊断中的提交号 | 建议构建/启动时注入完整提交号 |
| `BAIDU_APP_KEY` | 百度应用标识 | 可留空并由数据中心受限配置文件提供 |
| `BAIDU_APP_SECRET` | 百度应用秘密 | 不得提交或回显 |
| `BAIDU_REDIRECT_URI` | OAuth 回调地址 | 必须与百度开放平台完全一致 |
| `PERF_LOG` | 性能日志开关 | `1` 时启用 |
| `DERIVED_CACHE_DEBUG` | 派生缓存调试 | `1` 时启用 |
| `DERIVED_CACHE_LOG_THRESHOLD_MS` | 慢计算阈值 | 默认 120ms |

可从 `.env.example` 创建本地 `.env`，不要提交真实值。

### 5177 端口占用

PowerShell：

```powershell
Get-NetTCPConnection -LocalPort 5177 -ErrorAction SilentlyContinue
Get-Process -Id (Get-NetTCPConnection -LocalPort 5177).OwningProcess
```

确认是本轮启动的测试进程后再停止；不要盲目结束未知服务。也可临时设置 `PORT=5178`，但 Compose、Nginx 和 OAuth 回调仍必须使用各自真实入口。

## 6. 数据库

2026-10-17新增 `lessons.student_fee_mode`（standard/rule）：迁移默认standard，不更改已有金额；新排课写入rule，历史导入保持standard。完整Excel v7隐藏映射保留该可选字段，旧备份缺失字段按standard恢复。

2026-10-14新增可空 `teacher_monthly_performance.performance_score`，整数0—100；幂等添加，不回填旧分数、不改旧 K。清空评分保留现有系数，评分/系数原子保存，完整Excel v7隐藏映射支持往返。

主库默认是 `data/liming-local.sqlite`。活动数据库可能同时存在 WAL 和 SHM，不能仅复制主库文件来宣称获得一致在线备份，也不能仅凭 WAL 非空断言其中一定有尚未合并的已提交页。

主要表按领域分为：

- 教务：`lessons`、`teachers`、`students`、`student_grade_stages`、`class_groups`。
- 费用：`pricing_standards`、`student_pricing`、`fee_overrides`、`recharge_records`、`student_opening_balances`。
- 薪资与运营：`salary_tables`、`salary_table_rules`、`teacher_monthly_performance`、`salary_table_templates`、`salary_table_template_rules`、`teacher_salary_rules`、`teacher_adjustments`、`teacher_adjustments_monthly`、`teacher_travel_fees`、`staff`、`staff_salary_monthly`、`staff_attendance`、`operating_expenses`。
- 权限：`users`、`roles`、`role_permissions`、`user_page_permissions`、教师绑定和筛选预设表。
- 治理：`operation_logs`、数据检查表和 `backup_records`。

`npm run init` 和服务启动会执行幂等建表及兼容迁移。当前重要兼容规则包括：

- 期初余额已迁移为每名学生一条全局记录，表中不再保留 `month_key`；冲突记录必须先人工处理。
- `backup_records` 在旧表上按缺失列增量扩展，旧业务归档记录仍保留，不自动迁移、登记或清理。
- 角色权限和个人覆盖会校验白名单；历史老板/教务等角色名称由别名映射兼容。
- 调度设置保存在 `settings`，本地与百度频率、时间、重试、保留和操作日志选项相互独立。
- `recharge_records.channel` 与 `recharge_records.channel_other` 由幂等迁移补充；允许值为 `wechat`、`cash`、`alipay`、`other`，旧记录保持空值，不自动猜测或改写。
- `backup_records` 增加 `job_status`、安全错误码、任务时间和 worker PID 等异步任务列；不保存 Session、Token、App Secret 或远端 dlink。

2026-09-26：启动迁移复用 `src/domain/recharge_date.js`，历史空充值日期只按原有效业务月份补为当月 1 日；已有合法日期不改写，冲突的 `month_key` 按日期对齐。无法确定月份或日期非法的记录保留并计入 `unresolved`，不猜测当前月份；旧零金额 `carry_over` 占位记录单独保留。迁移使用保存点并输出数量，不输出业务明细；重复启动不会再次修改已处理记录。本轮没有新增数据库字段，也没有对正式数据库执行迁移。

旧 SQLite 运维脚本仍存在，适合停机维护或迁移演练：

```powershell
npm.cmd run db:backup
npm.cmd run db:export-json
npm.cmd run db:export-postgres
```

数据库恢复会覆盖主库，必须停服务、核对路径并保留恢复前副本，参见 [数据库迁移说明](docs/database-migration.md)。

## 7. 权限与账号

系统角色为老板、教务、小助手、助教、老师：

| 角色 | 默认范围 |
| --- | --- |
| 老板 | 全部页面和管理能力；兼容 `owner`、`boss`、`admin`、老板、管理员等历史值 |
| 教务 | 排课、学生、教师、经营和多数设置；默认不含数据中心和账号管理 |
| 小助手 | 日常课程、学生费用、充值和档案，兼容历史 `finance`；偏只读/有限写入 |
| 助教 | 课程、截图、学生和教师查询；偏只读 |
| 老师 | 课程、本人课时/教师信息及外观；可配合教师绑定限制数据范围 |

## 8. 课程与费用口径

- 课程状态候选来自基础数据，默认包括待上、已上、请假、试课、考试、未缴费。是否收费和是否计教师薪资由共享领域规则决定，不应在页面、Excel 和报表中各写一套。
- 学生实际费用优先使用单节覆盖 `fee_overrides`。历史课程保持standard来源，无覆盖时采用机构标准；本版新建课程使用rule来源，已上时优先采用有效个性规则，没有有效规则则回退机构标准。旧课程不自动迁移，规则变化不会将其改成个性价收费。共用课程弹窗展示最终实际费用、当前有效个性规则优先且无个性规则时回退机构标准的规则费用；旧standard来源不因个性规则变化而重算实际费用；新rule来源在无手动覆盖时跟随有效规则。
- 教师薪资仅统计“已上”课程，课次仍按课程行数。新表覆盖范围按共享公式实时计算自动基础课薪并保留单节特殊覆盖；新表范围外继续使用旧持久化金额，旧规则只通过显式操作写回。基础课薪、绩效及车费口径见下方新工作流，缺规则或必要系数时明确提示。
- 期初余额是全局起点，不是某月余额；月末计算结果不得回写成期初余额。
- 充值分实际充值和赠送充值。扣费按系统统一账本规则消耗余额，实际余额与赠送余额分开呈现。
- 跨月查询从全局期初余额开始，累计截至目标月份的有效充值和收费课程；请假、试课等状态按领域规则处理。
- 金额统一按人民币元存储和展示，禁止通过浮点格式化结果反向改写数据库原值。
- 首页课程日期、时间段和“当前时间”均按北京时间业务语义解释，不依赖 Node 进程或浏览器所在时区。时间区间采用开始含、结束不含规则，结束时刻立即移除；跨午夜课程归属于开课日期并延续到次日结束时刻。
- 薪资汇总和车费明细的教师候选都来自页面所选月份中确有课程记录的教师；档案在职、历史规则或其他月份车费不会单独生成候选。该月有课程的离职教师和薪资为 0 的教师仍显示，教师账号再按本人绑定范围收窄。

详细口径和审计背景见 [财务数据流审计](docs/financial-data-flow-audit.md)。

### 规则批量设置与页面布局

学生单价和教师薪资规则表的第一列都是显式复选框。表头全选只作用于当前筛选后的可见行，并正确显示全选、未选和不确定态；改变筛选会移除已隐藏行的选择，离开页面后重新进入会清空选择。点击普通表格行不会改变选择。批量弹窗分别调用 `PATCH /api/student-pricing/batch`（`{ ids, price }`）和 `PATCH /api/teacher-salary-rules/batch`（`{ ids, salary }`），金额范围为 0 到 100000 元且最多两位小数。

后端先去重并完整校验 ID、金额、条数、页面权限、只读状态和教师绑定范围，再在单一事务中只修改 `custom_price` 或 `salary_per_unit`。不存在的 ID 返回结构化失败且整批不写入；教师账号不能修改其他教师规则。成功响应包含 `processed`、`success`、`failed` 和最新 `rows`，页面只合并返回行并取消成功选择，不重新请求整份 bootstrap，因此当前筛选、月份和滚动位置保持不变。两类操作都写入安全的审计事件和操作日志，并触发规则、课时明细、首页、财务和汇总缓存失效。

薪资规则工具栏在 1440px 和 1280px 下将教师、搜索、价格状态、隐藏离职说明、筛选计数、选择计数、清空选择、批量设置、清筛和新增操作保持同一基线，控件高度差不超过 1px；390px 下按逻辑分组换行且不产生页面级横向滚动。首页桌面端不使用固定卡片高度：待办或人数统计的自然内容决定网格行高，三张卡底边一致；当前课程标题固定在卡内，只有课程列表滚动。移动端取消尺寸隔离，卡片按内容自然堆叠。

### 2026-10-15：单行表格与大课程量交互

### 自适应表格、字段对齐与充值渠道行内编辑（历史实现）

以下保留旧实现供追溯。其中学生集合/备注换行、柔性列填满及文本框自动增高已由上方2026-10-15规则替代；充值渠道交互与API约束继续有效。


费用明细、充值记录、期初余额、学生单价、班级管理、薪资规则、教师档案、账号和角色表统一使用 `applyAdaptiveTableColumns()`。函数按当前可见行线性扫描每列，读取内容并复用 Canvas 文字测量缓存，不逐单元格读取几何尺寸；文本框高度按批次写入、读取、再写入。最终宽度同时受列的 `type`、`minWidth`、`maxWidth`、`grow`、`wrap` 和 `alignment` 约束，不再让最长备注或全部学生标签总宽决定整表宽度。选择列固定为 44px，其余宽度通过各表 `colgroup` 一次性写入；内容总宽不足容器时仅由备注、学生集合或权限集合等柔性长列按权重吸收剩余空间，达到上限即停止，超过容器时按实际宽度展开。所有表格只由最外层 `.table-wrap` 横向滚动，单元格没有独立横向滚动条或 `resize` 手柄，`body` 不产生页面级横向溢出。

测量只发生在首次渲染、筛选结果变化、月份/页面变化、相关数据保存后的重新渲染，以及经过 120ms 合并的必要窗口尺寸变化。页面切换和连续渲染使用递增令牌丢弃旧任务；相同字体和文字的 `measureText` 结果保存在共享缓存中，算法复杂度为 O(当前可见行数 × 列数)，不创建逐单元格 `ResizeObserver`，也不监听滚动或鼠标移动。充值渠道局部保存后只重算当前表列宽，不重新加载 bootstrap。

所有表头统一水平、垂直居中，正文按字段语义对齐：充值记录的学生/年级/日期/渠道居中、两列金额右对齐、备注左对齐；期初余额的学生/年级居中、两列金额右对齐、备注左对齐；学生单价的学生/年级/科目/状态居中、学生集合和备注左对齐、单价右对齐；班级管理的老师/年级/科目居中、学生集合和班级名左对齐；薪资规则的老师/年级/科目/价格状态（内含启停控件）居中、学生集合和备注左对齐、薪资右对齐。短字段保持单行，长字段在有上限的列内自然换行；所有金额列和输入使用 `tabular-nums`，表头不会继承正文的左右对齐。

`salary_per_unit` 是每 `unit_hours` 小时金额，当前页面按每 2 小时维护。2 小时返回完整金额，1 小时和其他可识别时长按比例折算；0 元是有效规则金额并显示 `¥0.00`，字符串数字可安全转换。时间段无法识别、0 小时或规则课时口径无效时不再默认按一课时猜算，而是返回“无法计算”及安全原因。

规则启用状态兼容 `1/0`、布尔值、`启用/停用`、`在用/禁用` 和英文历史值。旧版同步候选以 `is_active=0` 创建，旧编辑器只保存金额而未同步激活状态；因此“状态为 0 且已有正金额”只在读取时按历史已配置候选兼容，不会改写数据库。0 金额候选仍视为未配置；新建、保存和显式启用写入 `1`，今后的显式停用写入 `-1`，从而不再混淆候选占位与用户停用。薪资规则页当时提供明确启用复选框（2026-09-26 改为点击主状态打开启停浮层，底层规则不变）。相同条件若有多条可用规则且没有既有优先级，则返回 `ambiguous`，不再静默选择最新一条。

2026-09-27 前页面明确展示以下五种结果；当前规则薪资列仅显示匹配金额（包括 0）或“无规则”，下述诊断状态仍由 API 返回，批量处理详情仍展示安全原因：

- **匹配成功**：显示规则金额；如果课程状态不参与实际计薪，仍显示金额并附“当前状态不参与计薪”。
- **未匹配**：显示“未匹配”和教师、年级、科目或学生集合的安全原因。
- **规则不可用**：显示“规则不可用”以及停用、未生效、已失效、金额或课时口径无效等原因。
- **存在多条匹配规则**：显示歧义状态，必须先整理规则，系统不会自行选择。
- **无法计算**：显示课程时长等安全诊断，不显示空白、`undefined` 或 `NaN`。

非成功结果旁的“查看匹配详情”列出教师、年级、科目、学生集合、规则状态、规则日期、课程时长和课程计薪状态。详情不包含 SQL、数据库路径、堆栈、其他教师规则、学生电话、监护人或余额。规则是否匹配与课程是否参与实际计薪是两个独立维度：不参与计薪的课程可以有完整规则核对金额，但批量更新仍按现有业务口径跳过。

勾选课程后点击“按规则更新所选薪资”，请求只发送去重后的 `lesson_ids`，不接受前端指定的新薪资。服务端按 ID 重新读取并校验权限，在事务中逐条重新匹配规则，只更新 `teacher_salary`、`teacher_salary_source='auto'`、`teacher_salary_rule_id` 和更新时间，不修改规则表或课程其他业务字段：

- **更新**：课程参与教师计薪、存在可用规则，且实际薪资与最新规则薪资不同。
- **无需更新**：实际薪资与规则薪资按当前金额精度已经一致；不计为跳过。
- **跳过**：明确区分未匹配、规则停用/无效、规则歧义、无法计算和课程状态不参与计薪，原因沿用服务端规则解析；2026-09-27 起规则薪资列简化显示，具体原因保留在批量处理详情。
- **失败**：无效或不存在的 ID 会返回具体原因；越权 ID 在写入前返回 403。

返回结果包含所选、更新、无需更新、跳过、失败计数和逐课程结果。页面显示“已处理 N 节课”汇总，并可展开“查看详情”核对日期、教师、年级、科目、学生、处理结果和原因，不再只提示“全部跳过”。完成后局部重载当前教师和日期范围：更新与无需更新行取消勾选，跳过/失败行保留，日期和教师不丢失，滚动位置尽量恢复。所有写接口仍受后端页面权限、角色写权限和只读状态校验；只读账号可查看但返回 403，不能靠绕过按钮执行更新。

批量操作写入审计事件和操作日志，记录操作人、所选数、更新数、无需更新数、跳过数及失败数，不记录密码、Session、Cookie 或完整请求体。薪资规则新增、修改、启用、停用以及批量写入都会使课时范围、规则列表、首页、财务与薪资汇总相关的前端 GET 缓存和服务端派生缓存失效；课时明细范围请求还会主动跳过五分钟 GET 缓存。保存后下一次进入或局部刷新即可读取最新结果，无需重启服务或 `Ctrl+F5`；强制刷新只用于取得新版本静态 JS/CSS。

### 学生年级阶段冲突

`student_grade_stages` 中同一学生任意两条有效阶段记录，只要闭区间日期有交集，就属于年级阶段时间冲突。起止日期端点相同也算重叠；同一阶段重复、不同阶段交叉、一段完全包含另一段均按相同规则检查。普通阶段只有起止日期都有效时参与判断；空日期不据此推测范围；“已毕业”阶段从起始日延续到未来。系统不会为了通过预检而自动改日期、合并或删除记录，也不会自动修改学生当前年级。

历史界面（2026-09-27 前）：进入“学生 → 学生档案”后，顶部“阶段冲突检查”区域始终显示，并明确区分四种状态：初次进入或重新请求时显示“阶段冲突：正在检查……”且按钮禁用；成功且结果为空时显示“阶段冲突：未发现冲突”和“重新检查”；存在冲突时显示“发现 N 名学生存在年级阶段时间冲突”、冲突组数、“查看冲突”和“重新检查”；接口失败时显示安全的“无权限查看”“接口不存在”“服务器处理失败”或“网络连接失败”以及“重试”，不会把服务端内部错误、SQL、路径、会话或 Token 渲染到页面。重新检查会跳过前端请求缓存，切换页面后再次进入学生档案也会重新查询。

2026-09-27 起，状态改为“新增学生”右侧的紧凑按钮：无冲突显示绿色“阶段冲突 0”，有冲突显示警示色“阶段冲突 N”，按学生去重计数；加载时禁用，失败时显示安全原因并可点击重试。无冲突按钮可重新检查；有冲突时点击进入原详情弹窗，弹窗保留重新检查、定位编辑和关闭后焦点恢复。

顶部人数统计的是当前账号权限范围内的全部学生阶段数据，不受学生、年级、状态、当前月份、分页、当前滚动范围或“显示历史（含已流出）”开关影响。老板账号统计包括在读、暂停、已毕业和已流出在内的全部学生；教师账号仍只统计其绑定课程范围内可查看的学生。表格筛选只决定当前列表可见行，不会改变顶部总数。点击冲突列表中的历史学生时，页面会自动勾选“显示历史（含已流出）”，在必要时清除阻止定位的姓名、年级和状态筛选，然后显示该学生、打开阶段编辑器、滚动并聚焦冲突阶段；系统不会自动修改日期。

有冲突时，表格姓名附近继续显示每名学生的冲突数量。点击“查看冲突”可查看学生、当前年级、两组阶段及日期、实际重叠范围和原因；点击“修改该学生”或表格标记会打开现有阶段编辑器并高亮冲突日期。学生档案表的复选框、姓名、当前年级、状态和日期列水平/垂直居中；姓名标签与“阶段冲突 N”标签按组合整体居中，长姓名自然换行；备注列保持左对齐，监护人和电话遵循当前统一表格规则。以上选择器仅作用于学生档案，不改变学生查询、课程总表、费用明细、教师档案或截图页面。

### 字段与安全规则

- 当前 `format_version=7`；兼容读取 `format_version=4`、`format_version=5` 和 `format_version=6`，缺少的新薪资/模板数据初始化为空，无教师归属的旧薪资表保留为未分配。新 v7 必须使用支持 v7 的应用恢复，避免丢失教师归属。
- 日期使用 `YYYY-MM-DD`，内部月份键使用 `YYYY-MM-01`，充值可见月份使用中文年月。
- 金额单位为人民币元；空值、显式空字符串和长文本使用固定映射规则。
- 用户文本会防止 Excel 公式注入；工作簿不使用宏。
- 密码哈希仅在 veryHidden 认证表中用于完整账号恢复；不会导出 Session、Cookie、Token、App Secret、服务器绝对路径或 Docker/SSH 凭据。

2026-09-22 历史实现：课程类型继续使用 v4 既有 `__关系映射` 保存不可见源字段，两段字典进入系统设置白名单；22 张可见表及其列契约、4 张 veryHidden 表、摘要校验均不变，因此不升级格式版本。已验证“导出 → 空库恢复 → 再导出”保留课程、班级类型及自定义候选。旧 v4/初始化模板缺少类型字段时补默认值；已有字段（包括显式空值）按原值恢复，空值可在下次启动补齐。含新字段的备份应使用本版本或更新版本恢复，旧应用的字段过滤器不会认识新增字段。

## 10. 数据中心

数据中心位于“设置 → 数据中心”，包括：

1. **数据完整性预检**：检查学生年级阶段冲突、角色关系、全局期初余额冲突、引用完整性和其他会阻止导出/恢复的问题；可查看安全摘要、CSV，并从阶段冲突直接前往学生档案修复。
2. **数据导入导出**：下载 v7、按需包含操作日志、下载模板、预览初始化导入或执行受控恢复；页面展示后台任务真实阶段及进度。
3. **服务器本地备份**：手动创建、自动开关、02:30（默认，Asia/Shanghai）、保留数量和日志选项。
4. **百度网盘备份**：配置应用、OAuth 授权、连接测试、独立频率/时间/保留和远端目录。
5. **备份记录**：区分旧业务归档和 `full_data_excel`，分别显示本地状态、百度状态、校验、失败原因、创建账号和备注。“固定”不再占用独立表格列，固定/取消固定入口位于操作区。

本地受管备份存入 `data/backups/full-excel/`，同时生成 `.sha256`。创建前执行数据预检，发布后验证工作簿和摘要；学生阶段冲突等数据问题会先阻止备份，避免生成语义不一致的恢复文件。下载响应设置 `no-store`。固定记录不参与自动清理；删除会保护旧体系、忙碌记录和最后一个有效成功备份，并分别报告本地 Excel、本地 SHA-256、百度 Excel 和百度 SHA-256 的结果。失败记录不受“最后有效备份”保护。只有四个组件都已删除或本来不存在时，服务才执行 `DELETE FROM backup_records` 并返回 `{ ok: true, deleted: true, backup_id, cleanup }`；此后列表刷新不会再出现该行，任务详情返回 404。任一组件失败时返回 409、`deleted: false` 和逐组件状态，数据库行保留为明确的“删除未完成”状态供重试。

备份创建人由 `created_by_user_id` 关联账号后生成语义标签：手动备份优先显示账号姓名，其次账号名；自动触发统一显示“自动备份”；账号已删除或关系已丢失时显示“已删除账号”；没有创建人信息的旧记录显示“历史记录”。API 同时返回 `created_by_label` 和 `created_by_type`，页面不显示原始数字 ID，也不会为旧记录伪造账号。

备份状态按执行位置解释：本地失败表示完整 Excel 未成功创建；本地成功、百度失败表示服务器副本仍有效，仅远端副本失败；Excel 与 SHA-256 只有一个完成时显示“部分失败”，不会笼统标成整个备份失败。失败记录从现有 `message` 和 `remote_error_safe` 读取稳定错误代码、中文原因及安全详情；学生阶段冲突至少显示第一条学生/阶段摘要和问题总数。历史记录若只有错误代码，会使用通用中文映射并明确提示“旧记录未保存详细信息”，不会伪造姓名或日期。

删除备份不再要求输入老板密码或“删除备份”，但仍有包含文件名和存储位置的普通二次确认弹窗。权限没有扩大，只有原本可删除备份的账号能够调用接口；固定备份、受管目录边界、路径穿越、符号链接、忙碌状态和最后有效备份保护均保留。删除结果及备份 ID、文件名写入操作日志，不记录凭据或远端下载地址。完整覆盖恢复、清空高风险配置的密码和确认机制不受此变化影响。

备份记录最左侧提供统一选择列，表头全选只覆盖当前可见且可删除的记录，并支持取消、半选、“已选择 N 条”和清除选择。运行中、固定、最后一个有效成功备份、旧体系或当前权限不可删除的记录会禁用复选框并说明原因；重新进入页面会清空选择，刷新会移除已不存在的 ID。“固定”仍位于操作区，不恢复独立固定列。

老板账号可通过 `POST /api/data-center/backups/batch-delete` 提交最多 100 个 `backup_ids`。接口去重 ID、拒绝空数组和超限请求、逐条重新查询并调用与单条删除相同的 `BackupService.deleteBackup()`，因此受管路径、符号链接、运行锁、固定、最后有效备份和百度双文件清理规则完全一致。批次不使用一个数据库事务包裹外部文件操作；一条失败不会阻止其他项，完全清理才物理删除 `backup_records`，部分清理失败则保留记录和逐组件状态。并发批量/单条删除由同一受管目录锁串行化，避免两份成功备份同时绕过最后一份保护。

确认弹窗汇总所选、成功/失败、本地/百度数量，不要求密码或确认文字。结果页显示处理、删除、失败和受保护数量，并可展开文件名、创建时间、创建账号、四组件清理状态及安全原因；不显示 SQL、堆栈、Token、dlink 或私密路径。成功行立即从 DOM 和选择中移除，失败行保留选择，受保护行统一取消选择，页面不会整体刷新或加载无关数据。批量操作日志只记录账号、数量、ID 摘要和安全结果，不记录请求体、凭据、远端下载地址或完整私密路径。

页面加载失败时应显示安全错误和重试入口；百度未配置、授权未完成或备份目录不可用都应降级为状态提示，不能让整个数据中心白屏。

此前学生状态优化轮次不新增数据库字段，自动数据变化是学生主档状态“离校”规范为“已流出”；2026-09-26 另有上文说明的充值日期兼容迁移。代码回滚应在停止服务并保留当前 SQLite 副本后，对本轮提交执行 `git revert`，再运行完整测试和数据预检。Git 回滚不会自动把“已流出”改回“离校”，也不会恢复已经物理删除的备份索引行及对应文件；前者如确有业务回退需要，必须在一致数据库副本上评估并执行受控反向数据脚本，后者只能从删除前另行保存且已验证的数据库/文件副本恢复。不要根据操作日志猜测重建备份文件。

### 2026-09-23：删除多余文件

备份记录区的“删除多余文件”先调用 `POST /api/data-center/cleanup/preview` 扫描，再展示本地/百度文件数、空间、关联备份、孤立文件及安全相对路径、时间、类型、原因；点击“确认删除”才调用 `/api/data-center/cleanup/execute`。两端均复用删除备份的老板高权限，只读 audit 不能清理，不额外要求密码。预览绑定账号、10 分钟有效、一次性使用；执行前重新检查记录、保留策略、目录、文件变化和新增引用。结果逐项返回，刷新备份记录及文件浏览，日志仅保留账号、扫描/删除/失败数量、空间、备份 ID 摘要与结果。

`src/backup/retention.js` 供自动保留与清理预览共用；有关联记录的备份只有各个现存副本均超出对应额度且允许删除时才入选，执行仍调用 `BackupService.deleteBackup()`。固定、忙碌、最后成功副本、共用文件引用、旧加密与未知历史记录继续受保护，四组件未完成时保留记录。

孤立清理只在当前本地受管根目录及配置的百度目录内识别系统命名的 Excel/SHA-256 完整配对，还要验证支持版本的完整 Excel 内容、摘要、无记录引用及同侧另有可确认恢复副本；不会仅凭名称或新旧删除。路径穿越、符号链接、隐藏目录和 `.secrets` 被排除，百度 fs_id 保持字符串。单个孤立 Excel 超过 50 MB、校验文件超过 4 KB、不完整或无法核实的失败残留均保留；单次最多预览 100 组，百度不可用时保护远端及关联远端的记录。孤立配对部分删除失败明确返回，剩余单文件不会在下次扫描中被冒充完整配对自动清除。重启后需重新扫描；本轮百度删除仅使用模拟 Provider 验证。

### 2026-09-26：清理预览异步任务与记录分页

旧预览虽然部分文件读取使用异步 API，仍在一个 HTTP 请求里等待本地遍历、百度分页及完整性校验，同步 SHA/工作簿验证还占用主事件循环。现改为 `POST /api/data-center/cleanup/preview/start` 立即返回 202 和任务 ID，独立 Node 子进程运行原扫描与保留策略；旧 `/preview` 路径也返回任务。`GET /api/data-center/cleanup/preview/:job_id` 只返回所属账号的阶段、状态和安全预览，重复点击复用当前任务，其他账号不能并发启动扫描。

页面立即展示扫描进度，每秒查询一次，离开或关闭后停止后续轮询；任务保留 15 分钟，清理预览仍按原 10 分钟有效期和二次确认执行。扫描阶段分本地、百度分页和完整性核对；本地附属文件读取每批最多 32 个，远端串行分页并设置请求超时与扫描预算。百度失败明确提示并保留可确认的本地结果，未知远端及关联远端记录保持受保护。实际删除仍复用 `BackupService.deleteBackup()` 或原孤立配对校验，固定、运行中、最后有效副本、路径、符号链接、旧体系及凭据边界不变；本轮只使用模拟百度 Provider。

备份记录由服务端分页，默认每页 10 条，可选 20/50 条，按 `created_at DESC, id DESC` 稳定排序；界面复用操作日志分页风格。最前列为全局连续显示序号，操作仍使用真实 `backup_id`，删除导致末页空缺时自动回退有效页。备份设置卡片收紧最小宽度，时区与长选项可完整换行。

### 百度手动备份的异步边界

`POST /api/data-center/baidu/backups` 只做权限、配置和数据预检，创建或复用唯一运行任务后立即返回 `202 Accepted`，响应包含 `backup_id`、`job_id` 和 `status`。前端提示“任务已开始”，通过 `GET /api/data-center/backups/:id/job` 轮询；重新进入数据中心也会从 `backup_records` 看到当前阶段和最终结果。重复点击复用现有任务，不创建第二份完整备份。

完整 Excel 导出、ZIP 压缩、工作簿验证、SHA-256、Excel/校验文件上传、远端回下载和完整性校验均由 `scripts/excel_backup/run_remote_manual_backup.js` 独立 Node 子进程执行。Web 主事件循环不再同步生成工作簿或等待百度网络，浏览器请求断开和页面关闭不会取消 worker，普通登录、课程和学生 API 不使用备份文件锁。任务仅在受管备份目录持有自身锁，不持有覆盖整个过程的 SQLite 写事务。

任务阶段为 `queued → preflight → exporting → hashing → uploading_excel → uploading_checksum → verifying_metadata → downloading_for_verification → integrity_check → success`，失败终态为 `partial_failed` 或 `failed`。worker 只接收运行所需路径、应用版本及百度应用配置，不接收内存 Session；记录只保存阶段和安全错误码。子进程异常退出由父进程标记失败，服务启动会检查遗留运行任务：PID 不再存活的任务标记 `BACKUP_WORKER_INTERRUPTED`，不会把半成品伪装成功。

旧实现的 504 根因不是 Nginx 超时太短，而是手动 HTTP 请求同步等待完整 Excel 生成、同步文件处理、百度双文件上传、回下载和校验；其中 CPU/文件同步工作还占用 Web 主 Node 进程，导致其他账号请求一起延迟。新接口不等待这些阶段，因此不依赖加长 `proxy_read_timeout`。后台失败只通过任务状态展示，避免“浏览器显示失败但稍后数据库又成功”的矛盾。

原写出器把全部 XML 以 ZIP method 0 原样存储，是 30 多 MB 的首要异常原因；操作日志还会同时进入可见日志表和完整恢复关系映射，是有恢复用途的内容而非无意义复制。旧文件中日志带来的增量为 14,825,359 字节，占含日志文件 38.36%。改为 Deflate 并取消整列金额样式后，含日志文件为 2,863,218 字节，减少 35,783,793 字节（92.59%）；不含日志为 1,765,877 字节，减少 22,055,775 字节（92.59%）。优化后日志增量为 1,097,341 字节。操作日志是否纳入仍由用户配置决定，完整恢复字段、隐藏表、摘要、金额和日期精度均未删除。

分析快照中各工作表的行数、列数、非空单元格数和使用区域由 `test:excel-size-analysis` 使用同一 ZIP/工作簿解析器统计；该测试还验证 Deflate、日志包含/排除、无整列金额样式、恢复到空合成库和再次导出。Microsoft Excel 人工打开仍属于发布前人工验收，不以自动解析替代。

## 11. 百度网盘备份

### 配置与授权

1. 在百度网盘开放平台创建应用，准备 App Key 和 App Secret。
2. 将数据中心显示的回调地址原样登记；正式环境必须是实际 HTTPS 地址。
3. 保存配置后发起 OAuth。回调路由是 `/api/data-center/baidu/callback`。
4. 回到页面时使用一次性 `?baidu=connected` 或失败标记展示结果，随后从地址栏清理参数。
5. 执行连接测试，通过后才允许启用远端自动备份，并确认“明文 Excel”风险。

App Secret 和 Token 存在 `data/backups/full-excel/.secrets/` 的受限 JSON 文件中，不回显。环境变量也可提供三项应用配置，但不要同时维护互相冲突的来源。

SQLite 中保存的是本地/百度备份的启用状态、频率、时间、保留数量、远端目录和明文风险确认等计划设置；百度 App Key、App Secret 与 OAuth Token 则保存在上述私密配置文件中。这是两套相互独立的数据。只复制 `liming-local.sqlite` 不会复制百度凭据，恢复或迁移数据库后必须在目标环境单独、安全地配置并授权百度网盘。

### 文件格式与下载链路

每次成功远端备份包含一对普通文件：

```text
黎明教育_全量数据_YYYYMMDD_HHMMSS.xlsx
黎明教育_全量数据_YYYYMMDD_HHMMSS.xlsx.sha256
```

Excel 是**明文**，SHA-256 只证明内容一致，不提供加密。上传完成后分别保存两个响应中的十进制 `fs_id`。下载链路必须是：

```text
上传返回 fs_id
→ filemetas?method=filemetas&fsids=[fs_id]&dlink=1
→ 取得 dlink
→ 携带 User-Agent: pan.baidu.com 跟随重定向下载
→ 下载配对 SHA-256
→ 校验摘要
→ 验证完整 Excel（v7 或兼容 v4/v5/v6）
```

`filemetas` 不使用 `path_list`。`fs_id` 可能超过 JavaScript 安全整数，代码在 JSON 解析前将其保留为十进制字符串，禁止转成 `Number`。正式下载使用记录中的 `remote_file_id` 与 `remote_checksum_file_id`；旧记录缺少 ID 时返回 `BAIDU_REMOTE_FILE_ID_MISSING`，不会猜测路径查询参数。

### 连接测试阶段

```text
authorization → connection → test_directory
→ file_upload → checksum_upload
→ file_metadata → checksum_metadata
→ file_download → checksum_download
→ integrity_check
→ test_delete_file → test_delete_checksum
```

测试只上传随机命名、无业务数据的文本和 SHA-256。核心测试与清理结果互相独立：核心失败仍尝试清理；核心通过但清理失败会给出警告；文件已不存在视为清理完成。

### 故障排查

| 阶段 | 常见错误 | 含义 | 处理 |
| --- | --- | --- | --- |
| `authorization` | 授权缺失/过期 | Token 不存在、已过期或刷新失败 | 重新连接百度网盘，核对回调地址 |
| `file_upload` / `checksum_upload` | API/分片失败 | 网络、目录、配额或百度服务异常 | 查看安全 provider_code，稍后重试 |
| `file_metadata` | `provider_code=2` | 常见为参数错误 | 确认运行版本使用 `fsids=[文件ID]`，没有 `path_list` |
| `checksum_metadata` | 列表为空或无 dlink | 校验文件 ID 不正确或文件已缺失 | 重新生成备份并核对双文件记录 |
| `file_download` | 403、31326、JSON 错误体 | dlink、权限、UA、有效期或服务端拒绝 | 确认 UA 含 `pan.baidu.com`，重新取得 dlink 后重试 |
| `checksum_download` | 下载失败 | SHA-256 文件不能读取 | 不得绕过校验；重新上传配对文件 |
| `integrity_check` | 摘要不一致 | 双文件不配对或内容变化 | 标记远端完整性失败，重新备份 |
| `cleanup` | 部分删除 | 核心结果不受覆盖，但测试文件仍在 | 按页面列出的安全相对路径人工核对 |

安全错误码包括 `BAIDU_FILE_METADATA_FAILED`、`BAIDU_CHECKSUM_METADATA_FAILED`、`BAIDU_DOWNLOAD_LINK_MISSING`、`BAIDU_FILE_DOWNLOAD_FAILED`、`BAIDU_CHECKSUM_DOWNLOAD_FAILED` 和 `BAIDU_REMOTE_SHA256_MISMATCH`。诊断只返回阶段、内部码、provider_code、HTTP 状态和清理状态，不返回 Token、授权码或完整 dlink。

旧 `.enc` 记录来自已下线的应用层加密方案，只保留兼容识别，不能当作当前明文 Excel 直接下载或恢复。

## 12. 自动备份与保留规则

调度器随 Node 服务启动，每分钟检查一次；它启动独立子进程执行到期任务，不使用 systemd timer。所有计划日期以 `Asia/Shanghai` 计算，数据库时间和导出 UTC 时间仍明确记录。

本地与百度调度互不依赖：

| 项目 | 本地默认 | 百度默认 |
| --- | --- | --- |
| 启用 | 否 | 否 |
| 时间 | 02:30 | 03:30 |
| 频率 | 每日 | 每周（也可手动/每日/每月） |
| 日志 | 不包含 | 包含 |
| 重试 | 3 次 | 3 次 |
| 保留 | 每日 14、月度 12、手动 20；本地总量初始至少 50（升级按现有数量安全取值） | 最近 20 份 |

本地 `schedule_key` 是 `full-data:YYYY-MM-DD`；远端键包含 daily/weekly/monthly 和计划日期。成功键唯一，服务重启会补查但不会重复成功任务。失败重试按 10、30、120 分钟等待。

百度远端计划只有在应用配置完整、OAuth 授权有效且已确认明文备份风险时才会启动子进程。未就绪时状态分别为 `not_configured`、`not_authorized`、`plaintext_not_acknowledged`，调度器不会创建任务，并且相同安全提示只记录一次；配置或设置变化后，下一分钟检查会重新读取 SQLite 与私密文件，无需重启服务。子进程仍会在执行前重复校验，若调度检查后发生竞态并返回 `BAIDU_AUTOMATIC_BACKUP_NOT_READY`，调度器会冷却 10 分钟，避免每分钟重复启动和刷屏。本地自动备份不依赖这些百度状态。

首个成功日备份可晋升为月度保留意义而不复制文件。固定记录不自动删除；任何清理都只处理当前受管格式，跳过忙碌/无效/最后一个可用备份。远端保留按配对文件删除，部分失败会保留独立状态，不能伪装为全部成功。

2026-09-23 补充：文件数量不等于备份记录数量。每个本地或百度副本通常包含 Excel 与 SHA-256 两个文件；每日、月度、手动和远端额度分别计算，固定记录、运行中任务、旧体系文件、失败残留和没有索引的孤立文件也可能继续占空间。“删除多余文件”只删除安全扫描确认的候选，不保证把目录文件数压到某个保留数字。

## 15. 恢复与回滚

### 代码回滚

代码回滚不应改写 `main` 历史：检出已验证提交或按提交边界执行 `git revert <commit>`，重新构建应用，再验证版本与核心页面。回滚代码不能自动回滚已经发生的数据库迁移。“本轮没有新增字段”仅适用于此前学生状态优化；2026-09-28 前两轮已新增薪资、模板表及课程来源字段，本轮又增加薪资表教师归属。回滚代码不会移除这些结构或恢复其旧语义，应先用一致副本演练；回滚本轮代码可按提交逆序执行 `git revert <本轮提交>`。已经由启动迁移写成“已流出”的学生状态不会随 Git 回滚恢复，已通过批量删除物理移除的备份记录和文件也不能由 Git 恢复，正式回滚前必须使用迁移/删除前的一致副本演练并明确恢复窗口。

### SQLite 回滚

必须先停应用写入，保留当前主库及 WAL/SHM，再从已验证的一致备份恢复。`npm run db:restore -- <backup>` 会覆盖主库且创建恢复前副本，只允许维护人员在核对绝对目标后执行。

### Excel 恢复

- 初始化导入：面向空系统，先预览再写入。
- 完整覆盖恢复：验证 v7 或兼容 v4/v5/v6、在临时数据库演练、确认备份和停机窗口，再执行覆盖。
- 手工可见表若被修改，隐藏关系和摘要可能不再匹配，应停止而不是强行跳过验证。

2026-09-26 回滚补充：Git 回滚不会撤销已补全的充值日期或已对齐的月份。需要回退数据时使用迁移前已验证的一致性副本，不能根据当前月份反推历史日期；本轮未对正式数据执行迁移或恢复。

### 百度备份

远端下载必须同时取得 Excel 和 `.sha256`，按记录的两个 `fs_id` 下载，先验 SHA-256 再验完整 Excel 版本及内容。缺少 ID、摘要不一致、旧 `.enc` 或下载失败都不能进入恢复。

数据库结构迁移完成后，旧代码可能无法读取新结构。正式回滚必须同时考虑代码、数据库副本和运行时版本，不能只切换 Git 提交。

服务端派生缓存 TTL 为 60 秒，键包含月份、账号 ID、规范角色、页面权限和教师绑定范围；老板、教务、只读覆盖和教师范围不会共用缓存。学生单价单条/批量/新增/删除、学生档案与阶段、课程及导入/审计修复会在请求开始和成功完成后失效；无关页面写入不会清除该缓存。前端另有同样 60 秒的会话内安全缓存：同键并发请求去重，切换页面用 `AbortController` 取消旧请求，旧代次不能覆盖新页面；单条或批量保存用服务端返回行修补当前内存缓存，不隐藏更新。

前端先立即显示标题、筛选器和“正在加载学生单价规则”，数据到达后同步渲染首批 36 行，再以空闲任务每批追加 72 行，显示真实进度并在离开页面或筛选变化时取消旧批次。没有传统分页或静默截断，最终全部筛选结果仍在同一表格中可滚动查看。选择状态保存在规则 ID 集合中，表头全选针对全部当前筛选结果而非当前 DOM 批次；半选、数量、滚动后选择、清空选择和最多 500 条的批量事务语义保持不变。学生单价行使用一个委托式事件入口，不为 1000 行重复创建相同监听器。

筛选键和学生集合在数据到达时预生成，学生、年级、科目、集合和价格状态使用一次线性过滤；服务端直接返回已去重排序的最小筛选选项，render 不再重复解析集合或反复去重排序。快速筛选会取消旧渲染批次；单条价格/备注保存只发送规则 ID 对应路径和变化字段，只更新当前行金额与备注；批量保存只发送去重 ID 和统一金额，只合并响应中的受影响行，不重新请求页面数据、不重载 bootstrap，也不丢失筛选、滚动和剩余选择。

### 语义列宽、自动离开日期与托管 Excel 浏览

`applyAdaptiveTableColumns()` 现在从每个 `<col>` 读取统一的 `type`、`minWidth`、`maxWidth`、`grow`、`wrap` 和 `alignment`。复选框、姓名、年级、科目、状态、日期、金额、账号、角色及手机号仍按表头和正常短内容测量，不做平均分配；备注等普通长文本限定为 160～360px，学生集合限定为 220～480px，权限集合或说明限定为 220～420px。只有 `grow > 0` 的柔性长列按权重吸收剩余宽度，达到上限后不再扩张；总宽超过容器时只由最外层 `.table-wrap` 横向滚动。长文本使用自动增高文本框自然换行，学生或权限标签在列内换行但单个标签不拆分，单元格没有横向滚动条或 resize 手柄。

该工具覆盖充值记录、期初余额、学生单价、班级管理、薪资规则、教师档案、账号表和角色表。教师档案的实际字段为选择框、姓名、电话、状态、入职日期、离职日期、备注；账号表实际字段为账号、显示姓名、角色、绑定老师、状态、重置密码、删除，角色表为角色名称、是否只读、编辑、删除。短列保持紧凑并按语义对齐，学生集合、绑定老师及备注作为有上限的柔性列。除上文说明的学生单价纯数据测量路径外，其他表仍采用 O(行数 × 列数) 的通用算法；渲染令牌继续阻止旧测量覆盖新页面，不会为单元格建立 `ResizeObserver` 或监听滚动、鼠标移动。

教师状态从非“离职”变为“离职”时，服务端调用共享领域服务重新查询最后课程日期；学生每次切换进入“已流出”或“已毕业”（包括“已流出”改为“已毕业”）时使用同一服务重新查询。教师姓名先 `trim` 后做完全相等匹配，不做模糊包含；学生复用 `splitStoredStudents()` 兼容现有合法分隔符和 JSON 数组，并做严格成员匹配。当前 `lessons` 表没有软删除或业务“无效”标记，项目删除行为是物理删行，因此有效范围定义为所有仍存在且日期通过完整日历校验的课程记录，不按 `lesson_status`、`course_status` 或 `status` 排除：已上课程和未来已排课程都纳入，取最大的北京时间业务日期字符串；无效日期和已物理删除行不纳入。计算只比较 `YYYY-MM-DD` 业务日期，不做服务器时区转换。

状态保存时即使客户端同时提交 `left_at` 或 `lesson_id`，后端也只信任自己的查询结果：找到课程则覆盖为 `{found:true,date,lesson_id,reason:"latest_valid_lesson"}` 中的日期；没有课程则保持空值并返回 `no_matching_lesson`，页面提示“未找到课程记录，未自动填写”，不会使用当天日期。修改其他字段不会重复覆盖已有日期，改回在职或在读也不会自动清空历史日期。状态变更及结构化计算结果写入安全操作日志，不返回完整课程或其他学生隐私。

## 17. 安全说明

- 百度网盘保存的是明文完整 Excel；SHA-256 是完整性校验，不是加密。不要公开分享文件或链接。
- App Secret 不回显；Token 和私密配置文件应为 0600，`.secrets` 和受管目录应为 0700。Windows 不具备相同 POSIX 位语义，仍需依赖账户 ACL。
- 普通 API/操作日志不得记录密码、Password Hash、Token、Cookie、Session、授权码、完整 dlink、App Secret 或服务器秘密配置。
- 下载响应应使用 `Cache-Control: no-store`，并由后端完成权限检查。
- Excel 本身包含学生、家长、教师、账号和财务敏感信息；隐藏工作表不构成保密措施。
- `.env`、真实数据库、源工作簿、上传、备份、证书、SSH/Docker 凭据均由 `.gitignore` 或部署边界保护，不得提交。
- Nginx 只代理应用，不应把 `/app/data` 或宿主机备份目录直接设为静态目录。
- 所有恢复、删除和权限变更都应保留可审计结果，并在隔离数据上先验收。

### 后续数据模型优化建议：重名学生（本轮未实现）

当前 `students.id` 虽存在，`students.name` 仍有唯一约束；课程的 `student_names`、班级的 `students_key` 是姓名集合，单价、费用覆盖、充值、期初余额、查询 URL 和年级阶段也以姓名关联。直接放开姓名唯一约束会造成去重合并、账单串人、班级匹配与 Excel 恢复歧义；仅禁止重名或把姓名改成“张三1”都不是长期方案。

建议保留不可变 `student_id`，另设唯一展示编号 `student_code`，姓名允许重复。课程、班级改用成员关系表，价格、费用、充值和阶段引用 ID；选择器显示“姓名（年级 / 编号）”，不附带不必要的隐私信息。

迁移顺序：先在一致性副本盘点姓名关联并生成唯一 ID 映射，歧义人工确认；再加关系表/外键并回填，逐项比对历史账单与人数；过渡期双读兼容旧姓名、写入同时维护旧投影，旧 API 遇歧义必须明确拒绝；最后切换查询与写入到 ID 后才放开姓名唯一约束。Excel 需同步新关系与编号、升级契约并提供旧 v4 转换和回滚演练。影响课程、班级、单价、费用、充值、余额、阶段、截图、查询缓存及导入导出/备份恢复，应独立立项分阶段实施。

## 18. 常见问题

### 5177 端口被占用

先用系统命令定位进程，确认归属后再停止；或临时换端口。本地直连端口、Compose 内部端口和正式 Nginx 入口不要混淆。

### 首次进入页面没有数据

确认已运行 `npm run init`，查看浏览器网络请求和 Node 日志；新合成库本来可以为空。不要用正式数据库来验证首次加载。

### Excel 版本不兼容或提示损坏

确认文件是当前 v7 或受支持的旧 v4/v5/v6，未被网盘预览器或办公软件改写，运行 `excel:full:verify`。若 Microsoft Excel 提示修复，文件不能用于恢复。

### 数据预检不通过

打开问题详情，按记录标识修正学生阶段、角色、引用、期初余额等源数据，再点击“重新检查”。学生阶段问题可直接前往学生档案定位冲突日期。不要删除整个旧库或绕过检查。

### 账号角色关系无效

在账号权限页将账号关联到有效系统角色；历史文本别名只用于兼容，不应继续生成新的非标准角色值。

### 期初余额迁移冲突

旧库同一学生可能有多个月份记录。必须人工判断唯一全局起点并解决冲突，不能把最近月末余额自动当期初余额。

### 百度授权失败

核对 App Key、App Secret、HTTPS 回调地址是否与开放平台逐字一致，以及服务器时间和 Token 状态。不要把 Secret 或 Token 粘贴到日志。

### 百度错误码 2

通常是参数错误。当前下载元信息接口必须发送 `method=filemetas`、`fsids=[正确十进制文件ID]` 和 `dlink=1`，不能发送 `path_list`。部署后先确认静态资源和服务端提交均已更新。

### 百度下载 403 或 31326

重新通过 `fs_id` 获取新 dlink，确认下载请求跟随重定向且 User-Agent 含 `pan.baidu.com`。不要缓存或记录完整 dlink。

### 测试文件已上传并删除，但测试仍失败

删除只说明清理完成，不代表核心测试成功。展开测试详情查看 `file_metadata`、`file_download`、`checksum_download` 或 `integrity_check`；核心结果和清理结果是两个维度。

### 浏览器仍显示旧样式或旧逻辑

先确认 `/api/version` 和部署提交，再强制刷新或清理该站点缓存。静态资源 URL 带版本参数，但代理/CDN/浏览器仍可能保留旧页面入口。
