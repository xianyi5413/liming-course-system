# 课程总表单行与性能验收（2026-10-15）

## 方法与边界

使用现有 `tests/helpers/chrome_cdp.js` 启动真实无头 Chromium，Windows 本机、Node.js v24.15.0、1440×900；临时 SQLite 中生成6000节课程，覆盖2026年365天、20种教师显示名、100个学生姓名，每课6人，10%含长备注。前端分别取500、2000、6000节；未使用正式数据或外部服务。

旧版本由独立 Git worktree 运行，提交 `0f4ed0aceba5a12ea38b911e7d2afcaacb35d205`；当前版本运行完全相同的测量代码。原始输出为 [优化前](performance/lesson-table-before.json) / [优化后](performance/lesson-table-after.json)。这是单次本机观测，包含运行环境波动，不是生产SLA；较小数据量的闲置菜单延迟不保证每次下降。

复现：`node tests/helpers/lesson_benchmark.js`。可用 `LESSON_BENCHMARK_OUTPUT` 指定JSON路径，用 `LESSON_BENCHMARK_ROOT` 指向已安装依赖的旧检出目录。脚本自行建库、登录合成老板账号并清理临时服务；不会读取项目data目录。

同步渲染为调用render到返回；后续等待为浏览器布局并响应下一次CDP检查的时间，含通信开销。菜单为真实DOM按钮click处理到两次requestAnimationFrame，包含浮层挂载、定位和可操作帧；不是操作系统鼠标硬件延迟。筛选后菜单为设置数学筛选、重建结果、处理排队的菜单打开动作到可操作帧，能反映主线程忙时的实际等待。

首次打开：登录完成后切换课程总表、加载全年范围并等待两帧。旧版全部课程进入DOM，当前版首个100条页面就绪；当前版不会自动渲染所有页，因此不能把首屏时间称作全部DOM渲染时间。数据没有截断。

## 根因与实现

1. 旧版整表innerHTML创建全部行，浏览/排课切换和筛选又重建，浏览器需处理数十万节点。现在共用100条分页、全量数据选择和统计、真实ID事件委托；不生成后台追加任务。
2. 本地冲突检查原为全范围两两比较，跨日期配对也执行。现在按日期分组，学生集合预解析，缓存完整结果，并按ID索引行级提示。仍校验全部筛选课程，保存时仍由服务端校验；同日极密集课程仍有二次复杂度。
3. 学生集合原列宽只考虑最长姓名并允许换行；现在公共列宽和学生单价数据测宽均计算全部标签，复用Canvas缓存。备注有界并提供全文，取消textarea逐个scrollHeight读取。规则薪资测宽取三行最大值，正文右侧14px留白。
4. 日期范围请求用序号、请求参数和页面校验拒绝过期结果；离页失效。姓名展示缓存有4096条上限，返回数组副本，业务规范化和财务算法不变。

## 验证范围与限制

新增大课程量专项覆盖500/2000/6000、完整全选/取消、末页序号、两种模式、长集合/备注、五种宽度、横纵滚动、表头一致性、学生搜索、连续年级筛选、日期请求竞态、离页响应、跨页真实ID保存和冲突缓存失效。已有回归继续覆盖批量修改/复制/删除/冲突确认、权限、领域金额、Excel与备份恢复。薪资测试新增真实表名三行元素、单行学生及14px右留白断言。

真实浏览器视口为1920、1440、1280、1024、390px；检查white-space、flex-wrap、行高、scrollWidth/clientWidth、页面溢出、sticky和对齐、Console与未捕获异常。旧“允许学生集合换行/长备注撑高”断言已替换为完整单行和全文可访问的更严格断言，未跳过失败用例。

没有验证正式数据库、真实账号、生产网络、真实手机硬件、超6000节规模，以及所有页面在每种账号/宽度/数据组合下的笛卡尔积。没有压测批量修改6000条：原接口最多500条且事务边界未改。Windows符号链接创建受环境权限限制的原有分支不等于实际执行了真实符号链接攻击场景。

最终完整回归495项通过、0失败、0跳过，耗时712.90秒；专项组合19项及表格序号专项4项通过，均0失败、0跳过；15个JavaScript语法检查及git diff --check通过。实现与验收完成时间：2026-10-15 07:53:29 +08:00（Asia/Shanghai），同步记录于README第16节及开发记录。
