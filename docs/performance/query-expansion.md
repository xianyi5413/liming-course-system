# 学生查询规则展开与批量费用验收

全部使用合成学生、临时SQLite和独立Chromium；不连接正式数据库，不部署。

## 实现与安全边界

主表13列，删除数量说明，恢复当前学生/范围的规则选择与批量设置，保留单条编辑。有效节数只计已上，总节数计当前范围全部真实记录；仅有待上课程的规则不进入主表。当前范围详情包括已上、待上、请假等状态，非已上显示不计费且不可选择收费。

展开复用课程表组件，一次请求全部当前范围的分组明细，大分组每48行让出主线程，小分组离线构建后每24组插入，工作约8ms也让出执行机会；代次和查询键阻止过期结果。父规则行使用一次索引，共享列宽只计算一次，窗口变化继续按组计算。折叠不请求明细。内联与弹窗共用独立的课程选择、真实后端预览和事务确认；规则选择与课程选择不混用。

按用户后续补充增加课程收费来源：已有课程standard，新建课程rule；已上新课程自动采用有效个性规则，没有有效规则回退机构标准，手动覆盖优先。恢复操作清除覆盖而不制造新覆盖。旧课程的个性规则与机构标准不同仍列为不处理，不迁移历史收费方式。金额相同无需写入，目标缺失不视为0。来源字段保存到v7隐藏恢复映射，可见Sheet不变，旧备份缺失字段按standard恢复。

预览有效期5分钟，绑定账号；确认前在事务内重读课程、规则、标准和覆盖并比对指纹。过期/变化返回409，越权拒绝；模拟第二条删除失败验证整批回滚。成功操作逐课程记录原金额、新金额和清除覆盖方式。历史消费和余额风险在确认弹窗明确展示。

## 性能比较

原始数据：[三轮基线与最终测量](query-expansion-comparison.json)。基线为主分支e181c84，使用临时隔离检出，不修改原工作分支。10/100/500节各属于一条规则，1000节形成1000条不同规则；每轮重新建合成库，因此包含第一次候选规则生成。初次交替测量后，因新增收费来源再次运行最终版本三轮；下面是默认折叠选择学生到查询完成的三轮中位数，单位ms。

测量期间另有完整回归负载，1000条样本波动较大，最终折叠路径变化为约+0.4%、+8.6%、−3.7%、+5.2%，不能据此宣称提速。本轮未做大规模性能重构；主要结论是默认折叠路径没有因预加载全部明细而退化。

另一个已预热夹具验证10/100/500节完整展开，以及1000条规则的全部课程展开；它与上表冷库测量口径不同，不直接比较。1000组额外压力测试曾超过30秒；合并列宽后单轮约20.55秒，其中列宽209.7ms，说明主要开销仍在逐组DOM插入和布局。再将小组离线构建并集中插入后，独立专项测得15.97秒、列宽224.4ms；这不是原版本对比，也不是多轮中位数。最终完整回归中10/100/500节分别完整展开60.9/172.2/776.9ms；1000组为13617.4ms、共享列宽139.4ms，原始数据见JSON的 `release_expansion`。所有课程必须完整且无重复，不能通过截断取得该时间。千组全部展开仍偏慢，应优先评估按组虚拟化；默认折叠不执行该路径。

## 兼容与限制

学生账单Excel仍按完整XML、文件名与原基线比较，复制图片仍按文字坐标、尺寸和固定生成时间PNG摘要比较；屏幕新增列不参与导出。恢复专项比较处理后的fee_overrides与恢复数据库，保留同课其他学生记录。

真实手机硬件、正式历史库和人工Excel打开未验收；Windows真实符号链接创建受EPERM限制。没有对个性规则不同于机构标准的历史课程实施收费迁移；新课程跟随规则及来源恢复单独测试。旧版程序不能保证识别新增来源，恢复新备份须使用本版或更新版。
