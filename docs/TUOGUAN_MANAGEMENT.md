# 托管管理实施与验收记录（2026-11-11）

## 架构与边界

沿用 Node.js 24、SQLite、原生前端，不增加运行依赖。统一关联 `students.id` 和 `teachers.id`，不生成普通课程、不计教师课薪、不读取或抵扣学科余额。原有课程账务使用姓名和元金额，不能直接用于托管的整数分日记账；因此复用认证、数据库连接、页面外壳、学生身份和完整备份，独立实现托管事务。

入口为“托管管理”：每日签到，以及学生、财务与设置。后者包含学生、流水、汇总、设置、导入核对标签。年级和班级在每个托管周期维护；已登记考勤保存当时的年级与班级。

| 表 | 用途 |
| --- | --- |
| tg_periods | 入托、暂停、退托、恢复后的新周期；含最后在托日期，拒绝重叠 |
| tg_rules | 全局或学生专属规则，按生效日期追加 |
| tg_calendar | 人工启用托管日期，关联值班教师、时段、请假截止时间 |
| tg_attendance | 学生与日期唯一，保存规则快照、金额、版本和待核对标志 |
| tg_ledger | 整数分资金流水；考勤更正追加冲正和新扣费 |
| tg_requests | 请求编号、内容摘要、已完成结果；重试不重复入账 |
| tg_audit | 操作人、时间、操作及变更记录 |
| tg_imports | 工作簿 SHA-256、排除餐费后的预览、异常和导入结果 |

启动时只新增表和索引，不修改旧课程数据。`BEGIN IMMEDIATE` 包住每个批次及流水，记录版本不符返回 409。规则调整不重算已有考勤；未登记、停课、不适用均为零。原始流水没有删除接口。现金充值、退款、优惠、调整和期初核定分别统计。余额允许为负；历史核定期初只能创建一次，后续差异使用有依据的调整。

## API 与权限

`GET /api/tuoguan/snapshot?month=YYYY-MM` 提供当月考勤、日历及相关档案。`POST /api/tuoguan/{period,attendance,money,rule,calendar,resolve}` 写入业务；`preview` 接受 XLSX base64，`import` 接受预览批次及人工身份映射。写操作必须携带 `request_id`；考勤、周期、日历和历史核对使用 `version`。

新增 `tgAttendance`（签到）和 `tgFinance`（托管学生、财务与设置）权限。老板沿用完整权限；其他账号由管理员显式授予。签到权限返回的数据不含费用、规则、余额、充值、导入期初或审计资金内容；普通教师无财务权限时不能调用财务写接口。只读账号前后端都禁止写入。当前签到权限表示机构范围的托管签到授权，不提供按班级限定教师的额外权限模型。

## 工作簿核对与字段映射

两个文件各含收费规则、学生信息、教师安排、三个年级考勤订餐、收费流水、收费总览，共八张表。含共享公式和缓存结果；总览通过学生编号、INDEX/MATCH、SUMIFS 等引用身份和流水。解析只读取缓存与原始考勤，不运行公式，也不修改 Excel。

| 原字段 | 处理 |
| --- | --- |
| 学生编号 | 只用于同一文件内部定位；不跨月认定身份 |
| 姓名、年级、班级 | 收费总览与逐日考勤交叉定位，必须人工选择统一档案 |
| 学生信息中的联系方式、入退托日期 | 因表头与部分内容错位，不盲目自动写入；人工检查档案 |
| 考勤日期 | Excel 日期序号转换，保留周末；空白为未登记 |
| 出勤、请假、缺勤、停课、不适用 | 导入历史考勤，初始全部待核对 |
| 非法考勤值 | 原值留在预览，按未登记进入待核对，不收费 |
| 正常费、请假费、缺勤费 | 用于独立重算和差异报告，正式核定前不入账 |
| 期初余额 | 单独保留待核对值，不能自动作为充值或连续月份结转 |
| 托管费总览 | 校验依据，不生成一笔汇总扣费 |
| 期末余额、净收款、总消费 | 不用于正式托管账本，可能包含餐费 |
| 所有订餐状态、数量、餐费 | 不保存、不导入、不参与计算 |
| 教师安排 | 非姓名内容存在异常，人工关联已有教师；不生成课薪 |
| 收费流水 | 两个原文件没有实际充值记录，不虚构流水 |

## 实际使用

1. 在原“学生档案”建立或核对身份，再添加托管周期。暂停或退托填写最后在托日，恢复时新增周期，避免覆盖历史。原系统姓名唯一，真正的同名异人须先人工解决身份，不能强行映射同一个人。
2. 设置收费生效日期（通常出勤50元、请假25元、缺勤50元）、人工日历和已有教师。日历逐日维护，支持周末。特殊标准选择具体学生。
3. 每日签到先选日期、年级、班级和姓名；逐人选择状态保存，或勾选后批量设置。月度矩阵支持横向滚动。未登记不收费；历史已结算记录更正时自动冲正。
4. 充值、退款输入正金额；调整可输入正负金额。填写经办方式、凭证和原因。汇总以账本计算结转、充值、退款、调整、消费和月末余额，并单列未登记、待核对数量；可导出 CSV。
5. 导入核对中上传原文件，检查人数、日期、状态、重算合计和异常，逐人映射档案。新学生需先建立档案。确认后只导入历史考勤；重复文件返回原结果，不重复扣费。不同来源与既有考勤冲突会整批回滚。
6. 当月待核对考勤逐条打开“核对并入账”，确认状态、三种费率和核对依据后才产生正式扣费。期初核定必须先排除餐费、重复结转等影响，再使用独立资金类型录入。历史月份周期仅用于保存历史范围，不代表已确认实际入退托日；后续新周期应核实真实日期。

## 备份与恢复

SQLite 全库备份自然包含新增八张表。完整 Excel 备份的内部恢复映射也已纳入八张表，保留原有22个可见业务表和v7格式；托管核对使用本模块CSV。使用当前版本的备份与恢复工具，旧版程序不能承担新增数据的恢复。旧工作簿恢复仍可用，恢复旧全库时托管表会随完整恢复清空，因此操作前务必备份当前全库。已测试完整导出后恢复全部托管表逐行一致及外键完整性。调度和远端副本沿用同一完整备份入口。
