# 教师绩效月份隔离与单课类型编辑

完成时间：2026-11-12 01:02（北京时间）。本轮仅修正前端月份归属、请求竞态和共享编辑接入，没有新增绩效表或改写历史薪资。

## 根因与修复证据

现有 `teacher_monthly_performance` 的主键是教师姓名与月份；`salary_store.js` 的 `coefficient()`、`score()` 及服务器PUT接口均按这两个条件读写。后端没有跨月UPDATE，缺失月份默认系数1.00，分数为空；缓存读取包含月份，写入沿用原缓存失效机制。

真实可复现的问题有两个：

1. 切换到10月时，全局 `state.settings.month_key` 先变化，9月输入框可能仍在等待加载期间显示。旧change处理器保存时读取这个可变月份，导致9月框里的值写到10月。修复后渲染时将行所属月份写入 `data-month`，保存立即捕获教师、月份、账号及会话版本，整个请求不再读取可变月份。保存期间禁用本框；失败恢复该输入原值。
2. `refreshDerivedForActiveMonth()` 未检查响应归属。连续切月时先发出的旧月请求可能后返回，将旧汇总、月份和输入值覆盖到新页面，造成跨月同步的观感。现在请求捕获月份、页面、账号及加载序号，只接受仍属于当前上下文的响应；切月立即使旧请求失效。

两项回归直接执行实际前端函数，修改前分别复现错误月份写入和旧响应覆盖，修改后通过。Edge另延迟10月bootstrap返回，在仍可见的9月输入框修改85分，数据库结果为9月85分、10月仍95分；释放加载后页面显示10月95分。刷新和月份来回切换仍保持各月独立。

## 保留的计算与清空规则

- 分数0—100整数；80分及以上系数为分数/100，60—79分为0.50，低于60分为0，沿用既有换算。
- 有分数时系数只读；清空分数保留该月已有系数，之后可手工调整。
- 清空手工系数删除该教师该月的绩效记录，回到该月默认1.00；其他月份不变，不复制上月分数。
- 跨月课程按各课程所属月份取系数并按原分摊、舍入规则计算。薪资汇总含车费，课时明细及经营概览的教师成本不含车费；比较时使用同一口径。

## 课时类型编辑

教师课时详情使用 `ClassCourseUI.typeCell` 和共享 `bindTypes()`，与班级管理共用原行内选择器及 `/api/class-groups/course-type`。保持原角色、班级管理页面权限和只读限制，类型候选按年级限制；提交 `mode: lesson` 和单个lesson ID，只更新这一节课。

班级身份仍由教师、年级、科目和归一化学生集合组成，不包含课程类型，因此类型修改不会拆班。请求成功使课程加载范围和派生缓存失效，重新读取教师详情及汇总；已关闭或切换的详情不被迟到结果重开。保留手工基础课薪优先级及原有学生收费规则。

合成验收使用两个月同班各一节课：1V1公式100+40K，1V2公式180+20K；9月K=0.50、10月默认1.00。仅将9月改成1V2后，仍是一行班级，9月工资190、10月140，详情、月度汇总及财务教师成本一致。原班级类型、批量类型、年级限制和只读交互也通过回归。
